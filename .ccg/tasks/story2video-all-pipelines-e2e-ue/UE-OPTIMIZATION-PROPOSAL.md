# 流水线参数 UI/UE 优化建议方案（待确认，确认后执行）

## 现状问题（本轮实测证据）

1. **非 story2video 的 13 条流水线会误导用户**：卡片外观与其他流水线一致，点击后展示完整表单（LLM 模型/温度/预算/检查点策略/视觉风格/输出设置），点击「启动流水线」后停留在 0%「进行中」且无任何真实执行（无执行引擎）。用户无法判断它是否可用。
2. **story2video-compose 参数密度仍较高**：基础区含 内容类型/图片生成器/基础说明，高级区同时混排 分句参数、模板（分类/选择/自定义）、输出设置（分辨率/帧率/格式）三类不同维度；声音区含 生成器/模型/音色 ID/克隆 等。
3. **无可用性信息**：列表页没有「可用/需要配置模型/未实现」标识，也没有入口引导到设置页配置缺失模型。

## 建议方案

### A. 流水线列表页（PipelineBrowser）
- 卡片增加可用性徽标：`可用`（story2video-compose）/ `开发中`（13 条无引擎流水线）；悬停显示说明。
- 未实现流水线卡片点击后进入详情，但**禁用「启动流水线」**，显示明确提示：「该流水线尚未实现执行引擎，暂不能生成视频」；避免 0% 停滞假运行。
- 卡片元信息展示「所需模型：LLM+图片+TTS」并在未配置时给出「前往设置」链接（复用模型服务商设置页）。

### B. story2video-compose 表单
- 基础区保持默认展开，摘要行已显示关键值（保持）。
- 高级区拆为两个子组：`分句与时长`（分句语言/模式/单句长度/分镜目标时长/无旁白时长）与 `模板与输出`（模板分类/模板/自定义模板/分辨率/帧率/格式），减少同一折叠区内的认知负担。
- 声音区：`语音 / 音色 ID` 下拉 + 克隆音色区（已完成）；补充「使用模型平台控制台音色」提示（Doubao 类）——需求 10 的说明文案。
- 所有受控默认参数（音调/并发/创意强度等）已在 UI 隐藏（符合需求 6），保持。
- 空态引导：未配置 LLM/图片/TTS 时，对应折叠区显示缺省提示 + 前往设置按钮（现状已有部分，统一化）。

### C. 通用（两处共用）
- 启动前校验提示统一走通知/对话框（已做），新增「未实现流水线」统一禁用态。
- 视觉回归：改动后需更新像素基线（`UPDATE_BASELINE=1 npm run test:visual:pixel`）并跑 Electron 路由 smoke。

## 建议执行批次（确认后）
1. 批次 1（低风险）：PipelineBrowser 可用性徽标 + 未实现流水线禁用启动 + 提示文案；同步 pipeline 注册表返回 availability 字段。
2. 批次 2：story2video 高级区子分组 + 缺模型引导统一化。
3. 每批次：Vitest + build:vue + 视觉基线 + Playwright Electron 路由 smoke；PR/CI/合并。

## 决策点（需要用户确认）
- 13 条无引擎流水线：是「先标为开发中并禁用启动」（推荐，本次实施），还是需要逐个实现真实执行引擎（工作量巨大，建议单独立项按优先级推进）？
