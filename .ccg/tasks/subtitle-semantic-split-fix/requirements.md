# 字幕语义边界修复需求

## 问题

在 `min=8/max=15` 时，用户文案会输出 `对汉地的管理极其粗放，江南`，而不是让逗号后的 `江南` 归入下一块；同时 `江南士绅摇身一变成了蒙元的包税人` 未在 `摇身一变｜成了` 处分块。

## 验收标准

给定用户原文，TS、Electron JS 与 smart-sentence-splitter Python 三端逐字输出：

```text
那时候蒙古统治者水平有限
对汉地的管理极其粗放
江南士绅摇身一变
成了蒙元的包税人
大汗把权力一下放
收税成本蹭蹭往下降
```

并且：

- `江南`、`蒙古`、`包税人`、`大汗` 不得被切开；
- 逗号切点优先于把后续完整短语吸附到前块；
- 三端共享规则保持同步；
- 既有字幕向量、parity、Electron 定点测试和 sidecar 测试通过。

## 追加需求：语义停顿

完整文案中的以下边界需要优先于“凑满最小字数”的短块合并：

```text
其实是跟南宋的老爷们｜提前谈妥了
之前蒙哥非要死磕｜还搞屠城｜吓得这些老爷们拼死抵抗
汉族地主阶级最爽的日子｜绝对是元朝
他们甚至嚣张到｜把大量蒙古人都卖去当奴隶
```

后块以语义引导字开头时，即使长度小于 `min_chars`，也不得被 `mergeShort` 吸回前块；硬切后若尾块以语义引导字开头，也不得再次触发平衡让字。
