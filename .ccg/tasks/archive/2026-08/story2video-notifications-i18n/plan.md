# Story2Video 通知、输入边界与双语支持计划

## 范围

1. Story2Video 失败只显示应用内弹窗，不再同时显示页面内错误条。
2. 删除所有按场景总数拒绝的路径；文本输入唯一上限为 6000 个 Unicode 字符。
3. 建立稳定的 `messageKey + params` 通知模型，并维护中文、英文两套用户文案。
4. 将 Story2Video 入口与结果页的错误提示收敛到该模型，默认中文且不泄漏底层英文技术错误。

## 实施顺序

1. 增加独立的 Story2Video 通知目录、语言选择和 Unicode 字符计数工具。
2. 用 RED 测试锁住双语解析、未知技术错误的安全回退、6000/6001 边界和无场景数拒绝。
3. 删除 `MAX_SCENES` 及 optimize、generate_assets、compose 中的拒绝分支；在文本合同层执行 6000 字符限制。
4. 在 CreateView 和 ResultView 使用统一通知模型，去掉重复页面错误条及原生 `alert`。
5. 运行聚焦测试、Vue 构建、Electron 打包和可视化验证；完成复盘、质量门禁与归档。

## 非范围

- 不取消媒体尺寸、总文件大小、总时长、单段时长、分辨率或并发等资源保护。
- 不更改 8002 分句服务或 Story2Video 生成算法。
- 不改动主工作区的未提交文件。
