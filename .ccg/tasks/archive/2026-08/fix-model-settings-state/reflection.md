## 问题

- 现象: 未新增模型服务商、未填写 API Key 的用户看到“已配置 52 个服务商”，默认页没有模型类别筛选标签。
- 预期: 预设服务商仅表示可选目录；只有保存 API Key 后才算用户已配置。默认页应保留类别筛选。
- 复现: 使用空的临时 Electron userData 启动打包应用，点击顶部设置。

## 根因（5 Whys）

1. 前端按 `api_key_masked || api_key` 计算“已配置”。
2. IPC 的 `_safeRow()` 对空 API Key 也初始化为 `****`。
3. 因此所有 52 个内置预设都带有非空掩码。
4. 前端无法区分“存在脱敏密钥”与“没有密钥的预设”。
5. 根因: 安全序列化的空值语义错误，且分层视图改造假定掩码只会在有密钥时出现。

## 逃逸链

- 单元测试: 覆盖了不返回明文和 `isConfigured()`，没有断言列表中的空 Key 必须没有掩码。
- 集成测试: composable 的 mock 使用空字符串，未覆盖真实 IPC 的 `****` 输出。
- 端到端/视觉测试: 未用全新 userData 打开模型设置并断言首次引导状态及分类标签。
- 代码审查: 未将“脱敏字段非空即已配置”的跨层契约列为检查项。

## 改进措施

[P0] 代码与单元测试:
  - 文件/位置: `model-provider-manager.js` 与 `model-provider-manager.test.js`
  - 改动: 空 API Key 返回空掩码；测试锁定全部空预设不被标记为已配置。

[P0] 状态/视图测试:
  - 文件/位置: `useModelProviderCrud.js` 与其测试
  - 改动: 类别计数以当前视图为准，测试覆盖 configured/all 切换。

[P1] 真实回归:
  - 文件/位置: 本任务 review 记录
  - 改动: 用独立临时 userData 的打包 Electron 自动化覆盖一次点击设置、零配置引导和六类标签。
