# Story2Video 模型提示弹窗

## 问题

已启用且保存了 API Key 的 LLM、图片和语音模型，在 Story2Video 运行路径上仍可能以“默认模型缺失”失败；现有失败信息出现在页面状态区或原生提示，难以理解和操作。

## 验收标准

1. Story2Video 未能解析必需模型时，向用户展示：`未找到需要的相关模型，请在设置中添加模型`。
2. Story2Video 启动与运行中产生的错误通过应用内弹窗展示，不调用原生 `window.alert`。
3. 关闭弹窗后页面保持可操作，错误运行状态仍可被历史记录追踪。
4. 现有默认模型的唯一已启用且已配置回退逻辑保持不变。
5. 覆盖后端缺模型文案和前端弹窗状态的自动化回归测试。

6. 当模型提供 HTTPS 图片 URL 时，Node 22 `lookup(..., { all: true })` 必须继续使用已验证的固定公网地址，不能放宽 SSRF/DNS 重绑定保护。
7. 真实桌面流程应记录 LLM、图片、语音均来自已选择的模型提供商，并以最终 MP4 的存在性和 `ffprobe` 解码作为完成依据。
