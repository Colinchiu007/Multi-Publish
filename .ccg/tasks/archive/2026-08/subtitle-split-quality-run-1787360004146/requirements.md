# 字幕分句质量修复需求

## 用户场景

项目 run_1787360004146_izko 的文案：

那时候蒙古统治者水平有限，对汉地的管理极其粗放，江南士绅摇身一变成了蒙元的包税人。大汗把权力一下放，收税成本蹭蹭往下降。

实际字幕出现了 江 / 南 的词语边界坏切：

    那时候蒙古统治者水平有限
    对汉地的管理极其粗放，江
    南士绅摇身一变成了蒙元的包税人
    大汗把权力一下放
    收税成本蹭蹭往下降

## 已确认根因

1. 在线 8002 结果只按去标点后的字符覆盖率验收；覆盖率达到 60% 时直接采用 scenes[].subtitles[].text，不检查相邻字幕块是否拆开词语。
2. 本地 v1.2.3 镜像依赖有限的 no_cut_bigrams，当前规则表未覆盖 江南、蒙古、包税人、大汗 等本次样例中的词。
3. 仓库中没有目标 run 的持久化快照、HTTP 响应或日志，因此不能仅凭最终文本确认该次运行走了在线 8002 还是本地回退；修复必须同时覆盖两条路径。

## 验收标准

- 同一文案走本地分句时，不产生 江|南、蒙|古、包|税人、大|汗 边界。
- 8002 返回包含 江 / 南 坏边界但覆盖率足够的字幕时，归一化层不得原样接受；必须修复为词边界安全的字幕块，并保留场景文本不变。
- 在线结果没有坏边界时继续原样采用，不改变既有 subtitleSource=smart-sentence-splitter 合同。
- 发生客户端修复时来源标记必须可追溯，不能继续声称结果未经修改地来自 8002。
- 共享规则、TS/JS 镜像和必要的 sidecar 规则保持同步；既有字幕向量、parity 与定点测试通过。
