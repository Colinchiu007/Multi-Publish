# 需求增强：视频创作流水线进度弹窗与后台运行

## 需求判断

本需求属于 M 复杂度、中风险的前端状态机与 UI/UE 改造，影响 CreateView、通用 UiModal、进度内容、国际化、测试和产品文档。运行时代码必须在独立 codex/s2v-progress-modal-background worktree 分支开发，并经 PR 合并。

## 用户可见目标

1. 编排视频流水线启动成功后，前端保留当前页的前台跟踪能力，完整阶段进度统一放入弹窗。
2. 运行中恢复【后台运行】按钮。点击后只脱离前端跟踪，任务继续由主进程执行；页面回到新建任务初始态。
3. 点击进度弹窗右上角关闭按钮时执行同样的脱离逻辑，并显示“任务已转入后台运行，在历史记录中可查看”。弹窗关闭使用已有缩小缩放离场动画。
4. 弹窗必须展示原进度区域全部内容：总进度、百分比、已用时、摘要、阶段列表、阶段详情、子进度、合成时间说明、模型警告、BGM 提示；素材选择检查点仍需保留可操作性。
5. 底部固定操作条在弹窗打开时仍可操作，且不被弹窗遮挡或误关闭。
6. 其他视频创作入口的流水线进度采用同一视觉壳和关闭策略；不改变非流水线异步 loading、发布 timeline、静态阶段指示和独立分析状态。

## 关键流程

- 启动成功且 outcome 未完成/未失败：绑定合法 trim 后 runId，拉取快照，打开进度弹窗并建立 3 秒轮询/实时事件兜底。
- 右上关闭或点击【后台运行】：校验 runId 存在，且不是 scene_asset_selection 或内容政策等必须人工处理的 checkpoint；递增请求代际，停止轮询，清理前端运行态，不调用取消 IPC，主进程 run 继续执行。
- 脱离后 action bar 显示本地化提示，并回到 idle 初始态；历史记录负责观察后台 run。
- 完成/失败/取消：关闭进度弹窗并沿用既有终态处理；完成仍跳转结果页，失败仍走脱敏错误提示。
- 从历史记录显式重挂运行中编排 run：回到流水线页，打开同一进度弹窗并继续观察。

## 数据与显示校验

- runId 必须是 trim 后非空字符串；异步状态响应必须验证 runId、请求代际和组件存活状态。
- stages 必须为数组；阶段对象非法时安全降级；progress.percent 只接受 0..100 有限数值；非法数据不渲染进度条。
- context、checkpoint、providerWarnings 等只接受对象/数组的约定形态；原始堆栈、token、provider JSON 不直接显示。
- IPC 参数必须是 JSON 可克隆值；素材选择沿用现有 cloneForIpc 和 checkpoint 校验。
- 新增文案必须 zh/en locale 成对，renderer 不新增中文字符串字面量。

## 已识别的产品优化边界

当前普通非编排流水线的启动接口在 renderer 未暴露稳定 run identity，状态查询按流水线名称进行，无法安全实现按单任务的后台恢复/取消。因此本 change 统一其进度视觉容器和生命周期清理，但不伪造 run-scoped 控制；后续需单独补充普通流水线 runId/状态 IPC 契约后再扩展。

## 验收标准

- running 编排 run 同时显示进度弹窗、【后台运行】、【取消】；idle/人工 checkpoint 不显示后台按钮。
- 遮罩和 ESC 不关闭进度弹窗，右上关闭按钮关闭；存在缩小离场 class/样式。
- 关闭/后台运行不调用 pipelineCancel，停止轮询、清 run 状态、恢复启动按钮并显示指定提示。
- action bar 按钮在弹窗显示时仍可点击。
- 定向 Vitest、pnpm run build:vue、依赖解析、locale/CJK、diff check 通过。
