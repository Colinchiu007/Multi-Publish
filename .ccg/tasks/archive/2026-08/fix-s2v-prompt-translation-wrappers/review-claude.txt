## Warning 🟡

### W1. 「首个 `{` 独占」：包装文本含花括号时，真实 JSON 永远不被解析
**[story2video-stages.js:109, 126, 176]**

- **What**: `extractFirstJsonObject` 锁定文本中**第一个** `{`（`indexOf('{')`），从它开始平衡扫描，返回第一个平衡段（或 null），从不前进到后续 `{`。
- **Why**: 这恰好是被修复的包装场景的残余漏洞。当 LLM 在真正的 JSON 之前输出含花括号的前导文字时：
  - **未闭合 prose 花括号**：`注意 {没有闭合 {"0":"real"}` → 扫描到文本末 depth 未归零 → 返回 `null` → 真实 JSON 被跳过，静默落入逐行回退（probe 实测：`expect null`）。
  - **可解析的示例对象**：LLM 回显 system prompt 中的示例 `例如 {"0":"译文一"} 请返回 {"0":"真实"}` → 首个平衡段 `{"0":"译文一"}` **JSON.parse 成功** → 错误地把 `译文一` 当译文锁定（probe 实测：返回 `{"0":"译文一"}`）。这是「干净但错误」的失败，比旧的整段垃圾更难发现。
- **Fix**: 改为遍历每个 `{` 出现位置，逐个候选尝试（或返回候选数组，由调用方依次 JSON.parse）；优先接受首个**可解析**的平衡对象：

  ```js
  function extractFirstJsonObject (text) {
    if (typeof text !== 'string') return null
    for (let start = text.indexOf('{'); start !== -1; start = text.indexOf('{', start + 1)) {
      // 从 start 做现有平衡扫描...
      // on depth===0: const cand = text.slice(start, i+1)
      //   try { JSON.parse(cand) 成功则 return cand } catch { 继续下一个 { }
    }
    return null
  }
  ```
  注意把 JSON.parse 移入函数会改变签名语义（当前职责是纯提取、parse 交给调用方）；更小侵入的替代是把「首个平衡段未 parse 成功则继续找下一个」放进调用方。LLM 输出受 `max_tokens` 约束，退化为 O(n²) 也可接受，但应保证每个 `{` 的扫描短路。

### W2. 测试覆盖缺口：字符串转义 / 嵌套路径零直接测试，首花括号边界未锁
**[story2video-stages.test.js:3044–3063]**

- **Why**: 新函数核心复杂度在字符串转义（`\"`/`\\`/`\\\"`）与嵌套/数组内对象，但三条新测试的 JSON 值都是纯中文无花括号、无引号转义，**这些路径在仓库内零测试**；`extractFirstJsonObject` 未导出，只能经 `translatePromptsForLocale` 间接到达，未来重构可能静默破坏。W1 的两个失败场景（prose 含未闭合/可解析花括号）也无测试锁定。
- **Fix**: 至少补两条回归：
  1. `例如 {"0":"示例"} 请返回 {"0":"真实"}` → 期望取 `真实`（若采纳 W1 修复）；
  2. 字符串值含花括号/转义引号：`{"0":"译文 {备注} \"引号\""}` → 期望 `译文 {备注} "引号"`。
  可选：为便于直接单测，导出 `extractFirstJsonObject`（`module.exports` 或 `exports.extractFirstJsonObject`）。
