# Story2Video 合成可观测性需求

## 目标

当合成任务长时间停留在 87% 或其他耗时阶段时，日志必须能回答：任务是哪一次、当前阶段是什么、FFmpeg 是否启动、是否仍在运行、输出是否增长、何时退出、是否超时、最终产物是否存在。

## 范围

- compose() 生命周期、阶段开始/成功/失败。
- FFmpeg 阶段统一记录启动、成功、失败、超时和输出缺失。
- 分块合成记录 chunk 开始、完成、失败和周期性心跳。
- 片段编码、旁白、BGM、WebM、输出校验和最终持久化统一关联 composeId。
- 日志使用 logger 的 meta 参数；不写完整路径、完整命令、素材内容、token 或密钥。

## 验收标准

1. 同一合成链路所有结构化事件含稳定 composeId。
2. 每个耗时 FFmpeg 阶段至少存在 started 与 succeeded/failed/timeout 之一。
3. 分块阶段含 level、chunkIndex、totalChunks、elapsedMs 和输出大小。
4. 超时和输出缺失可区分，错误包含安全的阶段码和截断 stderr。
5. 现有进度契约保持不变，日志增强不改变 FFmpeg 参数和执行顺序。
6. 测试覆盖成功、失败、超时、分块和敏感信息脱敏边界。
