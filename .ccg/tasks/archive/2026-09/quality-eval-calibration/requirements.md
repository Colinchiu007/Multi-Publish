# 改写内容质量评估 v1.1 校准与适用性口径

## 已交付基线

- 已合并的 v1.0 提供 15 个量化维度、改写完成后的自动评估、运营中心单篇评估及最近 100 篇统计。
- 本任务不重复实现上述功能；只处理当前评分语义的校准、可解释性和展示/统计一致性。

## 本任务目标

1. 非克隆改写没有原文时，克隆差异度必须明确为不适用，且不得影响综合分、低分建议或维度均值。
2. 结构化模板首先、其次、最后不能同时被逻辑维度识别为模板化，又被结构维度作为真实分点加分。
3. 真实书面第一人称叙事和个人观点必须获得有限、可解释的人类表达信号，不能只奖励网络口语。
4. 离线校准集必须同时约束人工参考样本平均分、模板上限、区分度、单字情感词误报及上述边界行为。
5. 改写引擎质量报告、运营中心单篇结果、最近 100 篇统计和前端展示必须携带一致的适用性语义。
6. 更新专项文档、相关 PRD/架构说明、CHANGELOG、质量门禁和复盘记录。

## 明确不在本任务内

- 不把缺少真实 LLM 凭据时的离线校准称为真实 100 篇改写验收。
- 不修改外部 content-aggregator-shared 的改写 Prompt 或供应商调用。
- 不在本任务中打通 AggregationService 改写结果到 ops-center SQLite 记录；该跨进程持久化缺口单列隔离任务处理。
- 不把易读性或关键词密度误当作 AI 检测器；模板文本可以易读或关键词聚焦，但仍可因去 AI 味和逻辑性低而不达标。

## 验收标准

- 全部校准测试通过：人工参考集平均 >= 70，模板集平均 <= 62，区分度 >= 8。
- 无原文的克隆差异度为 applicable=false，不参与总分和最近 100 篇该维度均值；带原文时仍参与。
- API 保持 15 个维度对象，并为每个维度返回 applicable；前端将不适用显示为 N/A。
- git diff --check、Python 质量测试、ops-center API 测试和必要前端测试通过。
