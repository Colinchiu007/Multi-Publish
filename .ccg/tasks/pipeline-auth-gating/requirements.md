# 统一流水线未登录启动门禁与登录引导

## 背景

视频创作中的图片轮播流水线与其他流水线在未登录、会话失效或无权益时处理不一致：启动按钮仍可点击，后端拒绝后前端却进入运行状态、显示阶段清单并将按钮改为“取消”。这会误导用户，也使认证错误看起来像生成失败。

## 目标

统一所有流水线启动入口的认证前置门禁与认证失败恢复路径，确保未登录状态不发起流水线 IPC；后端认证拒绝不会进入运行态，并能引导用户登录。

## 用户可见需求

1. 当身份状态不是已认证、刷新中或离线已认证且存在有效用户 subject 时，所有流水线的“启动流水线”按钮必须禁用。
2. 禁用按钮下显示固定提示：`请先登录，再进行操作。`。
3. 未登录点击路径不得调用 `pipeline:start` 或 `pipeline:startOrchestrated`。
4. 登录状态已存在但后端返回认证/权益拒绝（当前 IPC 合同为 `code=-3`，或稳定错误文本匹配）时：
   - 使用稳定通知 key `story2video.access_denied`（普通流水线也复用同一认证提示合同）；
   - 不显示普通生成失败 `alert`；
   - 不创建或保留运行中的阶段清单、轮询计时器、取消按钮或 `orchestrationRunId`；
   - 关闭提示后打开统一登录入口，用户登录成功后重新点击“启动流水线”。
5. 已登录但没有对应权益与未登录在 UI 行为上都必须可解释；权益校验仍由后端负责，本次不擅自新增 Story2Video entitlement feature 映射。
6. 普通非认证错误继续沿用原有错误展示，不得被误归类为登录问题。

## 状态合同

| 状态 | 启动按钮 | 提示 | 是否调用流水线 IPC | 是否进入运行态 |
| --- | --- | --- | --- | --- |
| 未登录 | 禁用 | 请先登录，再进行操作。 | 否 | 否 |
| 会话刷新且有 subject | 可用 | 无 | 是 | 按结果 |
| 已登录无权益 / 后端 `-3` | 请求失败后结束 | 当前登录状态无法启动图片轮播，请先登录并确认当前账号有对应权益。 | 是 | 否 |
| 普通启动失败 | 可用 | 原有具体错误 | 是 | 否 |
| 成功启动 | 可用后进入取消态 | 阶段清单 | 是 | 是 |

## 登录入口

认证失败提示关闭后调用统一 identity composable 的 `signIn()`，不得复制登录流程或直接操作底层窗口。登录成功后不自动重复提交用户任务，用户重新点击启动。

## 调试 profile 与模型配置边界

固定 `ELECTRON_USER_DATA_DIR` 只用于同机调试复用 userData 与身份会话；它不等于已登录证明，也不是云端同步。模型配置保存在该 userData 下的 `multi-publish.db`，API Key 使用 Electron `safeStorage` 加密；从其他 profile 或机器复制数据库行时，密文可能无法解密，前端应按“未配置”处理并要求重新录入。

## 验收

- 未登录 GUI：所有启动按钮 disabled，显示登录提示，IPC spy 无启动调用。
- 已登录成功路径：图片轮播正常进入阶段清单并轮询。
- 已登录后端 `code=-3`：无普通 alert、无阶段清单、无取消按钮、轮询停止，关闭提示触发登录入口。
- 普通 `code=-1`：仍显示原有普通错误。
- 认证状态重新加载后，按钮状态与 `identity:get-state` 一致。
- 运行定向 Vitest、Vue build；真实 Electron 窗口验证固定 profile 与按钮行为。真实 Logto/provider 权益仍需外部账号验收。
