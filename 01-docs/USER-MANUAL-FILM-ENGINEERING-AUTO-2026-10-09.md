## 1. 这是什么 / 适合谁

### 一句话

**给一段文案，可选给几张参考图，选横屏还是竖屏、大概要多少秒，剩下从分场、拆镜、套提示词、绑参考图、批量出片到拼成一部成片，全部由程序做完；出片后还能单独改某一个片段。**

### 它解决什么问题

| 你以前的处境 | 自动模式怎么处理 |
|---|---|
| 会用画布，但要一镜一镜连节点、逐镜确认，几十镜下来很累 | 你只做一次确认，之后整批自动跑完 |
| 想省事，但直接把文案丢给视频模型，出来的片子前后不接、人物每镜都不一样 | 程序会把文案按影视工程的分场规则切开，逐镜套用**结构化提示词**（GEO 空间布局 / 动作时间线 / 音效 / 角色表演 / 正向约束），并做角色槽位映射与参考图绑定 |
| 出了片子，某一镜不满意，只能整批重做 | 可以只改那一段：改提示词或时长，然后**只重新生成这一镜**；已经生成好的镜头不会重复生成 |
| 怕一点按钮就开始烧钱 | 确认卡是**清单式**的：确认之前**不会发生任何模型调用**；改动过内容之后，会要求你重新确认一次 |

### 适合谁

- 你有一篇**成稿的文案**（故事、脚本、口播稿、分场大纲都行），想让程序直接产出成片。
- 你希望**快**：不想学画布的节点编排，也不想逐镜手填提示词。
- 你对画面一致性有要求，愿意准备几张人物/场景参考图（**可选**，不给也能跑，只是人物一致性会弱一些）。
- 你需要对成片做**局部返工**，而不是全片重做。

### 不适合谁

- 你需要对**每一镜**的镜头语言（机位、景别、运镜）逐镜手工打磨 → 用**画布**更合适。
- 你想直接研究/复用现成的真实分镜提示词与方法论 → 用**工程案例**更合适。
- 你连大概时长都还没有概念 → 先用 30–60 秒试一篇短文，跑通流程再放长。

## 2. 三种模式怎么选

进入「影视工程」后，页面顶部有三个标签，从左到右是 **自动 / 画布 / 工程案例**。

| 维度 | **自动**（第 1 个标签） | **画布**（第 2 个标签） | **工程案例**（第 3 个标签） |
|---|---|---|---|
| 一句话 | 给文案与参考图，其余交给程序 | 节点式编排，逐镜可控 | 真实分镜库、剧本套用与提示词方法论 |
| 你的操作量 | 最少（1 次确认） | 中（逐镜连线、逐镜确认、逐镜重试） | 视用法而定（浏览/套用/复制/出片） |
| 是否能逐镜改提示词 | 能（出片后在片段编辑里改） | 能（节点里直接改） | 能（复制/导出后使用） |
| 是否能逐镜重试 | 能（失败或不满意的镜可单镜重生成） | 能 | 能（分批出片通道） |
| 成本确认方式 | 一次聚合确认，覆盖整批 | 逐批确认 | 逐批确认 |
| 适合的时机 | 想要**成片**，且不想管细节 | 想要**精细控制**，且了解镜头语言 | 想**学习和复用**《Hell Grind》这套真实分镜与提示词方法论 |

标签上还带一行悬停提示（鼠标停在标签上会显示）：

> - 自动：「填剧本、参考图、横竖屏与大概时长即可；程序自动完成分镜规划、参考绑定、批量出片与合成」
> - 画布：「节点式编排：剧本拆分镜、参考图连线注入、逐镜重试与成片」
> - 工程案例：「《Hell Grind》真实分镜库、剧本套用、提示词方法论与全量分批出片」

三个标签之间切换**不会丢失彼此的状态**：你从画布切到自动再切回来，画布上已经摆好的节点还在；自动模式已经填好的剧本和已经跑出来的进度也还在。

## 3. 快速上手（5 步）

### 第 1 步：进入影视工程

从「创建」入口选择「影视工程」流水线进入；页面默认停在**自动**标签。

**你看到什么**：页头「影视工程」标题 + 一行副标题（三种用法的说明）+ 三个标签 + 四步步骤条：

> 步骤条依次是：**填写文案 → 确认清单 → 自动生成 → 收口合成**

**系统会怎样**：如果你是通过历史链接打开的页面并带了标签参数，会直接停在你上次看的那个标签；如果参数不是三个标签之一，会回落到**自动**。

### 第 2 步：粘贴文案

把成稿文案粘进「剧本」多行输入框。

**你可以做什么**：

- 直接粘贴全文。
- 用**空行**分隔场景（推荐）。例如：

```
第1场
小强推开门，屋里一片漆黑。他摸到墙上的开关。

第2场
灯亮的一瞬间，阿明站在他面前。两人都愣住了。
```

**系统会怎样**：

- 输入框下方实时显示字数，形如 `123 / 10000 字`。
- 超过 10000 字时，字数变红并出现提示「剧本超过 10000 字上限」，同时「生成预览」按钮不可点。
- 场景之间的空行决定**分场边界**；单独一行、看起来像场景标题的行（例如 `第1场`、`SCENE 2`、以 `INT.` / `EXT.` 开头的行）会被当作标题，与它下面那段剧情算作同一场。

### 第 3 步（可选）：加参考图

**人物参考图**：点「添加人物参考图」，选中本地图片；添加后在列表里给这张图填一个**角色名**。
**场景参考图**：点「添加场景参考图」，选图即可，不需要填名字。

**系统会怎样**：

- 图片会先被主程序**按内容验真**（只看文件头魔数，不信文件后缀/声明的类型），只接受 **PNG / JPEG / WEBP**，单张不超过 **10MB**；不合格会直接拒绝并给出原因。
- 通过校验的图片会被复制到受控媒体目录，列表里显示的是它落盘后的真实路径。
- 人物图最多 8 张、场景图最多 8 张；到达上限后添加按钮变为不可点。
- 人物图的**角色名**很关键：只有文案里**命中这个名字**的分镜，才会注入这张图。名字为空的图片不会被用于绑定。

### 第 4 步：设画面方向与大概时长

- **画面方向**：二选一，`横屏 16:9` 或 `竖屏 9:16`。
- **大概时长**：可以直接点预设（`30 秒` / `60 秒` / `90 秒` / `120 秒`），也可以在数字框里填 **10–600** 之间的整数秒。
- 需要的话展开「**高级设置**」，把「**单镜时长**」设成 `5 秒` / `8 秒` / `10 秒`（默认 5 秒）。

**系统会怎样**：这一行会实时跟着变：

> 预估 12 个分镜 · 实际时长约 60 秒（确认前不产生任何模型调用与费用）

### 第 5 步：生成预览 → 确认 → 等 → 收口合成

1. 点 **「生成预览」**（按钮文字就是这四个字）。这一步只做规划和估算，**不调用任何模型、不产生费用**。
2. 页面出现**确认卡**（章节 7），里面有分镜数、批次、时长对比、Provider、警告清单、角色槽位映射、**预计占用磁盘**、**预计耗时**，以及逐镜一览。
3. 勾选确认框，点 **「开始生成」**。
4. 进度区出现阶段清单、逐镜状态表，以及一个 **「停止生成」** 按钮；你可以继续用软件做别的事。
5. 需要的话点 **「停止生成」**：当前批次跑完后停下，**未开始的批次保持待跑**（不记为失败）；界面回到确认卡、勾选仍在，再点「开始生成」即从断点继续（章节 9）。
6. 全部镜头有了结论（成功或失败）后进入完成态：如果**没有缺镜**，点 **「收口合成成片」**。
7. 合成完成后，页面内可以直接预览成品，并有「打开所在文件夹」和「另存为」。
8. 想改某一段：在逐镜表里点该镜的 **「修改片段」**。
9. 忘了上次跑到哪了？直接打开自动标签即可——界面会自动挂回上次的任务并显示它的真实进度（章节 9）。

## 4. 页面骨架与导航

### 你看到什么

```
影视工程                        ← 页头标题
三种用法：自动（…）、画布（…）、工程案例（…）   ← 一行副标题

[ 自动 ] [ 画布 ] [ 工程案例 ]      ← 三个标签，当前标签高亮

（当前标签的内容区）
```

自动标签内容区从上到下是：

1. 四步步骤条：**填写文案 / 确认清单 / 自动生成 / 收口合成**（当前所处环节高亮）
2. 出错时的红色提示条（有错误才出现；平时看不见）
3. 「剧本」输入卡
4. 「人物参考图（可选）」卡
5. 「场景参考图（可选）」卡
6. 「画面方向」+「大概时长」卡
7. 「高级设置」（默认折叠）
8. 预估行 + 「生成预览」按钮
9. 生成预览后出现：确认卡（含**预计占用磁盘** / **预计耗时**；撞上同名任务时还会多出一个「覆盖同名任务」勾选框）
10. 开始生成后出现：进度区（阶段清单 + 逐镜状态表 + **「停止生成」按钮**）
11. 完成态出现：收口合成区（含成品预览与两个落盘按钮）

### 你可以做什么

| 操作 | 结果 |
|---|---|
| 点标签 | 切换模式 |
| 键盘 `→` / `←` | 在三个标签间循环切换 |
| 键盘 `Home` / `End` | 跳到第一个 / 最后一个标签 |
| 浏览器前进/后退（或改地址栏 `?tab=`） | 标签跟着变 |

### 系统会怎样

- 标签切换会同步到地址里（形如 `?tab=canvas`），**刷新页面后仍停在同一标签**。
- 只有你访问过的标签才会真正加载内容；没点过的标签不会提前加载，切换过的标签**不会被销毁**，所以进度与画布状态都不会丢。
- 历史链接 `/film-engineering/classic` 仍然可以直接打开「工程案例」页面（不带标签壳的独立页）。这一条是刻意保留的兼容路径，方便旧链接与文档引用继续有效。

## 5. 输入项逐项说明

### 5.1 总表

| 输入项 | 必填 | 取值范围 / 格式 | 超出时界面表现 | 提示文字（原文） |
|---|---|---|---|---|
| 剧本 | **是** | 1–10000 字（按去掉首尾空白后的长度判定是否为空；按原始字符数判定是否超长） | 空则「生成预览」不可点；超长则字数变红 + 按钮不可点 | 空：`请先勾选确认，再开始生成`（在启动环节）；超长：`剧本超过 10000 字上限` |
| 人物参考图 | 否 | 最多 8 张；PNG / JPEG / WEBP；单张 ≤10MB；每张需 1–20 字角色名 | 到 8 张后「添加人物参考图」不可点；上传不合格立刻弹错 | `最多 8 张，支持 PNG / JPEG / WEBP，单张不超过 10MB。可为每张图填写角色名；命中该角色的分镜会自动注入这张参考图。` |
| 场景参考图 | 否 | 最多 8 张；格式与大小同上；不需要名字 | 同上 | `最多 8 张，格式同上。按场景顺序轮转绑定，同一场景的分镜共享同一张参考图（与 GEO 空间布局「每场锁定」一致）。` |
| 画面方向 | **是** | `16x9` 或 `9x16`（界面显示为 `横屏 16:9` / `竖屏 9:16`） | 界面上只有这两个选项，选不出非法值 | 标题：`画面方向` |
| 大概时长 | **是** | **10–600** 之间的**整数**秒 | 非法时输入框下方出现红字提示，且「生成预览」不可点 | `时长需在 10–600 秒之间` |
| 单镜时长（高级） | 否 | `5` / `8` / `10` 秒（默认 5） | 下拉框里只有这三项 | 标题：`单镜时长` |

### 5.2 「剧本」详细说明

**你看到什么**

- 标题：`剧本`
- 输入框内灰色占位文字：

> 粘贴你的剧本或故事文案。按空行分隔场景；程序会自动套用影视工程的提示词架构（场景上下文 / GEO 空间布局 / 动作时间线 / 对白音效 / 角色表演 / 风格 / 正向约束）并规划分镜数量。

- 下方右侧实时字数：`123 / 10000 字`

**你可以做什么**

- 粘贴/编辑文本。
- 写场景标题行让分场更明确（`第1场`、`SCENE 2`、`INT. 客厅 - 夜` 等）。
- 在文案里直接写角色名，方便程序识别角色（章节 5.4 讲识别规则）。

**系统会怎样（分场与拆分规则）**

1. **分场**：以**空行**为界切段；若某段只有一行且形如场景标题，则把它作为「标题」，与紧随其后的正文算作同一场。
2. **只拆不并**：如果分出来的段数**少于**目标镜数，程序会把**最长的可拆段落**按句末标点（`。！？!?；;`）切成多段，**逐字保留**内容（不丢字），不够就继续拆下一长的段落；实在拆不动（例如整篇只有一句话）就**如实少出几镜**，**绝不会凭空造镜**。
3. **只并不拆**：如果段数**多于**目标镜数，程序把相邻段落**合并**到目标数，同样是保序、逐字保留、不复制内容。
4. 每一段最终对应**一个分镜**，并套用影视工程的提示词模板生成该镜的完整提示词。

> 一句话记忆：**拆**只发生在段不够时，**并**只发生在段太多时，两者不会同时发生，也不会为了凑数字丢字。

### 5.3 参考图详细说明

**人物参考图**

- 添加后，列表每一项是：一个「角色名」输入框（占位文字 `角色名（如 小强）`）+ 落盘路径 + 「移除」。
- **命中才注入**：某一镜的文案里出现了该角色名，这张图才会被注入到这一镜。没出现就不注入。
- **上限**：单镜最多注入 **2 张**参考图（人物图优先，剩下的名额给场景图）；同一张图不会重复注入。
- **最多 4 个角色槽位**：程序内部只有 4 个槽位（`ROKO` / `JAXX` / `LULU` / `REIN`）。检出的角色按**出现次数从多到少**依次占用这 4 个槽位；第 5 个及之后的角色**不会**被映射进提示词。
- 角色名长度需在 **1–20 字**之间；太长会被服务端拒绝（错误信息：`人物参考图必须含 1-20 字的角色名`）。

**场景参考图**

- 不需要名字。
- **按场景轮转共享**：第 1 场用第 1 张，第 2 场用第 2 张，用完一轮再从第 1 张开始；**同一场里的所有镜共用同一张**（与「GEO 空间布局每场锁定」的规则一致）。
- 与人物图共用「单镜最多 2 张」的额度。

**上传会被怎样校验（这是"假图片"进不来的原因）**

| 检查 | 不通过时的提示（原文） |
|---|---|
| 是否提供了图片数据 | `参考图数据（dataUrl）不能为空` |
| 数据格式是否合法 | `dataURL 格式非法` |
| 能否解码 | `dataURL 解码失败` |
| 内容是否为空 | `参考图内容为空` |
| 是否超过 10MB | `参考图不能超过 10MB` |
| 是否是真正的 PNG/JPEG/WEBP（**看文件头，不看后缀**） | `仅支持 PNG / JPEG / WEBP 格式参考图` |
| 落盘路径是否仍在上限目录内 | `参考图落盘路径越界` |

> 例：把 `.txt` 改名成 `.png` 上传 → 会被「仅支持 PNG / JPEG / WEBP 格式参考图」拦下，不会进入媒体目录。

### 5.4 角色是怎么被认出来的

程序按下面的**优先级**找角色（越靠前越"权威"）：

1. **你在人物参考图里填的名字**（最强）：只要文案里出现过这个名字，就算只出现 1 次也保留。
2. **显式标记**：文案里写了 `【角色：阿明】`，或某一行以 `名字：` 开头（台词行，如 `小强：走。`）。（注意：`阿明说道：` 这种**动词结尾**的不会被当成角色行。）
3. **对话动词前的名字**：紧跟「说道 / 说 / 道 / 喊道 / 喊 / 问道 / 问 / 答道 / 答 / 低语 / 开口」等词前面的 2–3 个字，且**在全文出现 ≥2 次**才采纳。
4. **停用词守卫**：`他们` `我们` `这个` `那个` `然后` `已经` 等常见词不会被误判成角色。

检出的角色按次数排序后填进 4 个槽位，确认卡上以「**角色槽位映射**」展示，形如 `ROKO → 小强`。

如果没有认出任何角色 → 确认卡出现 **W4** 警告（见章节 8）。

## 6. 时长与镜数是怎么算出来的

### 公式

```
目标镜数 N = clamp(round(大概时长 ÷ 单镜时长), 1, 120)
实际时长   = N × 单镜时长
```

- `round` = 四舍五入；`clamp` = 限制在 1 到 120 之间。
- **上限 120 镜**。因为时长上限 600 秒、单镜最小 5 秒，`600 ÷ 5 = 120` 正好顶到上限——也就是说**合法输入永远不会被上限截断**，上限只作为异常输入的兜底防线。

### 对照表示例

| 大概时长 | 单镜时长 | 目标镜数 | 实际时长 | 界面会不会提示 W3 |
|---|---|---|---|---|
| 60 秒 | 5 秒 | 12 | 60 秒 | 不会（正好相等） |
| 60 秒 | 8 秒 | 8（60÷8=7.5 → 8） | 64 秒 | **会**（64 ≠ 60） |
| 22 秒 | 5 秒 | 4（22÷5=4.4 → 4） | 20 秒 | **会**（20 ≠ 22） |
| 7 秒 | 5 秒 | 1（1.4 → 1） | 5 秒 | 不会出现在界面上（10 秒是下限） |
| 600 秒 | 5 秒 | 120 | 600 秒 | 不会 |

### 实际时长与「大概时长」不一致怎么办

- 界面在确认卡上直接对比给你看：`约 64 秒（目标 60 秒）`。
- 同时给出 **W3** 警告，说明差异来自「单镜秒数 × 镜数」这个离散关系（提示原文里会写清算式）。
- 想更接近目标，办法是：改**单镜时长**（5/8/10 三档里选一档使乘积更接近），或改**大概时长**。
- **不需要**为了凑准数字去改文案：镜数是由时长决定的，文案只会被拆/并到这个镜数上。

### 段落不足时会怎样

若文案能切出的段数少于目标镜数，且已无法再拆（比如整篇只有一句话），程序会**如实产出更少的镜**，实际时长随之变短，并给出 W3。**不会**为了凑数字复制内容或生成空镜。

## 7. 生成预览（确认卡）逐项说明

点「生成预览」之后出现的卡片，是你**唯一需要认真看**的一屏。

### 标题

> 生成预览（尚未产生任何调用与费用）

这句话是字面意思：到这一步为止，程序只做了文本分析与提示词组装，**一次模型调用都没有发生**。

### 显示项逐项说明

| 显示项 | 含义 | 取值/示例 |
|---|---|---|
| **任务 ID** | 这次任务的名字。程序自动生成（形如 `auto-` 加日期时间），也参与"这份计划属于谁"的校验 | `auto-20261009163000` |
| **分镜数** | 这次要生成几个镜头 | `12` |
| **批次** | 执行时会被分成几批（每批 10 镜）。分批是内部的顺序化机制，不影响你要做的事 | `2` |
| **时长** | 实际时长与目标的对比 | `约 60 秒（目标 60 秒）` |
| **画面方向** | 你选的方向 | `横屏 16:9` |
| **视频 Provider** | 将用于出片的视频模型来源。没配置时显示「未配置」——但**正常情况下没配置就无法进入这一步**（会先报错） | `未配置`（异常态） |
| **注入参考图的分镜** | 有多少镜真的用上了参考图（命中角色的镜数） | `3` |
| **预计占用磁盘** | 按每镜约 8MB 估算的磁盘占用（不足 1GB 显示 `MB`，达到 1GB 显示 `GB`）。**续跑恢复出来的会话不显示这一行**（那时不重算规划，见章节 9） | `96 MB` / `1.2 GB` |
| **预计耗时** | 按每镜约 5 分钟估算的墙钟时长（不足 1 小时显示 `min`，达到 1 小时显示 `h`）。同样只在刚生成的预览里显示 | `1.0 h` |
| **需要注意** | 警告清单（W1–W7），没有则不显示这一块 | 见章节 8 |
| **角色槽位映射** | 检出的角色被放进了哪个槽位 | `ROKO → 小强` |
| **逐镜一览** | 每一镜一行：镜号（如 `auto-000`）、场次标题、**提示词字数**（如 `1240 字提示词`）、有无参考图（🖼 加数字） | 见下 |

### 为什么逐镜只显示"提示词字数"而不显示提示词本身

- 提示词很长（每一镜都是几百到几千字的完整结构化提示词）。120 镜全部搬到界面上，会让页面变卡，而且确认卡也不需要你看全文——你要判断的是「几镜、多长、有没有参考图」。
- 完整的提示词**安全地存在服务端的计划文件里**。等你真的要改某一镜时，程序按镜把内容取回来给你编辑（章节 11）。
- 顺带一个好处：界面上不搬运全文，就不存在"界面显示的提示词"和"真正发给模型的内容"不一致的可能。

### 确认框与按钮

**勾选框文字（原文）**：

> 我已知悉：将生成 {镜数} 个分镜（约 {秒数} 秒成片），确认后才会开始调用视频模型

**勾选框下方的提示（原文）**：

> 确认后程序将自动完成分镜规划、参考绑定、批量出片与合成；中途可停止，已完成的镜头不会重复生成。

**「开始生成」按钮**：勾选框**没勾时按钮是灰色的（不可点）**。

> 未勾选时点不了；即便绕过界面直接调接口，服务端也会拒绝执行——这是"确认前零调用"的双重保险。

### 你可以做什么

| 想做的事 | 怎么做 |
|---|---|
| 改文案重来 | 改上面的剧本，再点一次「生成预览」（会生成一份新计划） |
| 改方向/时长 | 同上，改完重新生成预览 |
| 加减参考图 | 改完重新生成预览（参考图变化会改变计划的"身份"） |
| 只是不想现在跑 | 什么都不用点。计划有过期时间，过期后需要重新生成预览 |

### 系统会怎样

- 确认卡的每一项都来自服务端算出来的**计划**，界面不会自己推算（界面上的「预估 N 个分镜」只是给你填表时看的粗略估算，真值以确认卡为准）。
- 计划一旦生成就**不会被悄悄改**；改了输入就得重新生成预览。
- 计划有**有效期 24 小时**，且**用过一次就作废**（防止同一份计划被反复重放）。注意这**不影响续跑**：续跑同一个任务不再需要计划（章节 9）。
- 如果这次启动撞上「同名任务已存在且不是同一份计划」，确认卡上会出现一个 **「覆盖同名任务」勾选框**：

  > 覆盖同名任务 {任务ID}（旧一轮的产物与确认历史会归档保留）
  >
  > 仅在确认要用这份新计划替换同名任务时勾选；不勾选不会改动既有任务。

  勾选后再点「开始生成」才会带上覆盖标记；旧一轮的项目文件与执行记录会被移进该任务的 `archive/<旧轮次>/` 目录保留（章节 14）。**不勾选则不会动既有任务**。

## 8. 警告码对照表（W1–W7）

警告**不阻断**流程——它们出现在确认卡的「需要注意」区，每条形如一个短句。它们的作用是"先告诉你，再让你决定"。

| 码 | 什么情况会出现 | 影响 | 建议动作 |
|---|---|---|---|
| **W1** | 当前的视频 Provider **不支持参考图输入**，而这次确实有分镜要注入参考图 | 参考图会被忽略，这些镜**降级为纯文本出镜**（不会报错，照常出片） | 人物一致性会变弱。若参考图很重要，换成支持参考图输入的 Provider，或接受纯文本效果 |
| **W2** | 分镜数**超过 10** | 程序会自动分 `⌈镜数 ÷ 10⌉` 批顺序执行；**不需要你逐批确认** | 无需处理。只是让你知道"跑得久一点是正常的" |
| **W3** | 实际时长与「大概时长」**不相等** | 成片时长会与预期有偏差（差多少看算式） | 想更接近就调单镜时长或大概时长，然后重新生成预览 |
| **W4** | **没检出任何角色** | 提示词里的角色行会**沿用模板自带的角色标识**（不会替换成你的角色名，也不会凭空造一个"占位名"）。提示原文：`未检出角色，分镜将沿用模板自带的角色标识；可在人物参考图中填写角色名以提升人物一致性` | 两个办法：①在人物参考图里填上角色名（最有效）；②在文案里显式写 `【角色：X】` 或让角色名出现 ≥2 次 |
| **W5** | 墙钟预估**超过 2 小时**（程序按每镜约 5 分钟估） | 不影响正确性，但等待时间会很长 | 建议缩短时长、增大单镜秒数（减少镜数），或分成几次跑 |
| **W6** | 参考图路径**没有通过受控目录校验**被跳过（属于纵深防御；正常上传的图片不会触发） | 被跳过的参考图不参与注入 | 重新添加参考图（重新上传会回到受控目录内）。若反复出现，属于异常，请反馈 |
| **W7** | 规划出的分镜里有**没解析到文案**的镜。典型情形：整篇只写了一行场景标题（比如单独一行 `INT.`），程序会把这一行当标题、给不出剧情文本 | 这些镜的提示词里没有一点你的文案，只有模板结构。**不阻断**，照常出片 | 把这些场的剧情文字补上，再重新生成预览。提示原文会列出受影响镜号（最多 5 个）：`有 N 个分镜没有解析到文案（剧本里可能只写了场景标题行），这些镜将沿用模板原文：#1, #2` |

> 说明：W5 的提示文字里写有「支持停止与断点续跑」。这两件事**在当前版本都已可用**：运行期有「停止生成」按钮（批间生效），重新打开自动标签会自动挂回上次的任务继续跑——详见章节 9。

## 9. 运行期：进度、逐镜状态、离开与续跑

### 你看到什么

点「开始生成」后，确认卡收起，出现进度区：

1. **四步步骤条**跳到第 3 步「自动生成」。
2. **阶段清单**（沿用故事讲述流水线的同一套进度组件）：
   - 顶部进度条 + 百分比 + 摘要行：`已完成 5 / 12 镜`
   - 三段：**规划**（已完成）→ **自动生成**（进行中，带子进度条与 `已完成 x / y 镜`）→ **收口合成**（未开始）
   - 每段有状态图标：`○` 未开始 / `⟳` 进行中 / `✓` 完成 / `⏸` 暂停 / `✕` 失败
3. **逐镜状态表**（4 列）：`分镜` / `状态` / `失败原因` / `操作`
4. **「停止生成」按钮**（只在运行中出现）。点了之后按钮立刻置灰并显示 `正在停止…`，同时弹出一条提示：`已请求停止：当前批次跑完后停下，未开始的批次保持待跑（再次点开始即从断点继续）`。

| 列 | 内容 |
|---|---|
| 分镜 | 镜号，形如 `auto-000` |
| 状态 | `待生成` / `生成中` / `已完成` / `失败`（实际只会出现前三种里的 `待生成`、`已完成`、`失败`；`生成中` 是保留状态） |
| 失败原因 | 失败时的具体原因（例如超时、Provider 报错）；成功时为空 |
| 操作 | `修改片段`（改这一镜）、`重新生成`（只重跑这一镜） |

进度区下方有一行提示（原文）：

> 生成期间可继续操作界面；关闭页面不会中断任务，重新打开可续跑。

### 你可以做什么

| 操作 | 结果 |
|---|---|
| 做别的事 / 切到别的标签 | 任务继续跑；进度不会丢 |
| 改某一镜的提示词 | 点该镜的「修改片段」（章节 11） |
| 重跑某一镜 | 点该镜的「重新生成」 |
| 关掉页面再回来 | **任务本身在主程序里继续执行**，已经生成好的镜头不会重做 |
| 中途不想跑了 | 点 **「停止生成」**（批间生效，见下） |
| 忘了上次的任务 ID | 不用记：重新打开自动标签会自动挂回上次的任务，并显示它的真实进度 |
| 想换一份新计划重来 | 改文案/参数后重新点「生成预览」（会拿到新的任务 ID，与旧任务互不影响） |

### 系统会怎样（内部行为，解释"为什么看起来这么稳"）

- **进度有两个来源**：①主程序主动推来的进度事件（优先）；②界面每隔 3 秒问一次状态（兜底）。两者结合，即使某一批的事件丢了，进度也能收敛到正确值。
- **事件的真实推送频率是节流的**（约每 0.5 秒最多一条），所以你不会被刷屏，界面也不会因为事件太多而卡。
- **每一批跑完之后，程序会去磁盘上点数**（而不是相信"生成函数说自己成功了"）：
  - 文件在 → 这一镜才算 `已完成`，并记下它的产物路径；
  - 文件不在 → 这一镜记为 `失败`，并保留失败原因。
- **一次只允许一个自动任务在跑**。如果你在任务运行期间又发起一个，会被拒绝（提示见章节 12）。
- **失败不会拖垮整批**：某一镜失败，其余镜照常继续；失败的镜留在表里等你处理。

### 关于「停止生成」的真实情况

| 说法 | 真实情况 |
|---|---|
| 点停止会立刻中断吗？ | **不会立刻中断**。停止是**批间生效**的：当前正在跑的那一批会跑完（最多 10 镜），之后不再开始新的批。这是刻意设计——半途掐断的批次无法保证产物完整。 |
| 停下来的批次会被记为"失败"吗？ | **不会**。未开始的批次保持 `待跑`，不会被标成失败。 |
| 停下之后能接着跑吗？ | **能**。停止后界面回到确认卡、勾选仍是已确认（要生成的内容没有变化，所以不需要重新确认），直接点「开始生成」即从断点继续；已经生成好的镜由磁盘复核跳过，不会重复生成。 |
| 停止标志会一直留着吗？ | 不会。任务结束后停止标志立刻清理；对一个已经不在运行的任务再点停止，会如实回报「未在运行」（幂等，不会误伤下一次启动）。 |
| 为什么按钮点了就灰了？ | 已经请求停止、正在等当前批收口期间会置灰，防止重复请求。 |

### 关于"离开与续跑"的真实情况

| 说法 | 真实情况 |
|---|---|
| 关掉页面/切走 → 任务还在跑吗？ | **在**。任务在主程序里执行，页面只是观察者。回来后进度会自动显示（界面会自己查询状态）。 |
| 「重新打开可续跑」= 我可以关掉应用再回来接着跑？ | **可以**。界面会把最近一次的任务记在本机（存储键 `film-auto:last-task-id`）；再次打开自动标签时会自动读取它的真实状态：还在跑 → 直接进运行态并继续显示进度；已有结论但没跑完 → 回到确认卡等你点「开始生成」继续；全部有了结论 → 直接进完成态。**你不需要记住任务 ID**。 |
| 续跑靠的是什么？ | 靠**同名任务**，而不是那份计划：计划在第一次启动时就被标记为"已消费"（刻意的防重放设计），续跑要的信息全部来自**任务自己的项目文件**（每一镜的提示词、参考图、时长）。所以只带任务 ID 也照样能续。 |
| 已经生成好的镜会被重复生成吗？ | **不会**：每次执行前程序都会核对磁盘，已经存在的镜头直接跳过（标记为"已完成"），只跑缺的那几镜。 |
| 如果我换了任务 ID、或传了一份别的计划会怎样？ | 若传来的计划与既有任务不是同一份、又没有勾选「覆盖同名任务」，服务端会**直接拒绝**并提示 `同名任务来自另一份计划；如需覆盖请显式确认（旧一轮将归档保留）`——**不会静默覆盖**你已经生成的产物。 |
| 有"停止"按钮吗？ | **有**，见上一节。 |

## 10. 收口合成

### 什么时候可以点

完成态出现后，收口合成区显示：

- 如果有镜没成功：红字提示（原文）`缺镜 {n} 个：{镜号列表}`，并且 **「收口合成成片」按钮不可点**。
- 如果所有镜都有结论且都成功：按钮可点。
- 如果存在未完成的镜，界面也会在按钮上方给出（原文）`还有 {shots} 个分镜未完成，请先重新生成失败片段再收口合成`。

### 你可以做什么

1. 点 **「收口合成成片」**。
2. 合成期间显示（原文）`合成中（run {runId}，{percent}%）`，百分比会随进度走。
3. 合成完成后出现成品预览播放器，以及两个按钮：
   - **「打开所在文件夹」**：在文件管理器里定位到成片。
   - **「另存为」**：把成片另存到你选择的位置。
4. 想开始一个全新的任务：点 **「开始新任务」**（只把界面复位到填写状态；**不会删除**已经生成的文件）。

### 系统会怎样

- 点按钮时，程序先做一次**双重核对**：台账（记录每批执行情况的文件）说这批完成了吗？磁盘上文件真的齐吗？两者都通过才允许合成——**避免生成一份"清单说有、磁盘上没有"的假成片**。
- 缺镜时不到合成那一步就被拦下，**不会产生任何合成调用**。
- 合成这一步**不需要再确认成本**：因为它只是把已经生成好的片段拼起来（不产生新的视频生成调用）。
- 如果服务端发现清单收不齐，会返回（原文）`渲染清单未收口（…），缺失镜：…`；界面把它显示在错误条里。
- 合成完成后，成品路径由合成任务回传；界面据此显示预览与两个落盘按钮。若推送事件丢失，界面会通过轮询在几秒内补齐。

## 11. 片段修改（重点）

这是"生成后可以对某个片段进行修改调整"的入口，也是自动模式和"一次性出片工具"最大的差别。

### 怎么进入

在逐镜状态表里，点某一镜的 **「修改片段」**。编辑区在该镜下方展开。

### 你看到什么

标题：`修改片段 auto-003`，右上角一个「关闭」。

**左栏（可编辑）**：

| 控件 | 说明 |
|---|---|
| `片段提示词` | 多行文本框，装的是这一镜**完整的提示词**（从服务端取回的真值） |
| 字数 | `1240 / 50000 字`（上限 50000 字） |
| `恢复原文` | 一键把文本框还原成"打开时"的内容（丢弃本次未保存的改动） |
| `本镜时长` | 下拉：`5 秒` / `8 秒` / `10 秒` |
| 一行说明（原文） | `提示词会逐字符提交给视频模型，不做任何润色改写——这是影视工程「原文直送」合同。` |
| `保存修改` | 保存提示词（和时长，若你改过） |
| `按当前内容重新生成` | 按当前文本框里的内容重新生成这一镜 |

**右栏（预览）**：

| 内容 | 说明 |
|---|---|
| `片段预览` | 这一镜已经生成的视频（没有产物时显示 `该片段尚未生成，暂无可预览的视频`） |
| 状态行 | 例如 `状态: 已完成` |

**黄色提示（有缺块时才出现）**：

> 提示词缺少这些结构块：GEO SPATIAL LAYOUT / AUDIO（影视工程的提示词块是成片质量的关键；仍可保存，仅作提示）

### 块结构缺失提示是什么

影视工程的提示词由若干**结构化块**组成。编辑时会检查这 5 个块是否还在：

`GEO SPATIAL LAYOUT`、`ACTION TIMING`、`AUDIO`、`CHARACTER ACTING`、`POSITIVE CONSTRAINTS`

（判定规则：块标题必须**独占一行**才算是"有这个块"；正文里偶然提到这些词不算。）

- 缺块 → 黄字提示，列出缺了哪几个，并说明**仍可保存**。
- 这是**提示而不是拦截**：你完全可能有意精简提示词。
- 但请知道代价：少了 `GEO SPATIAL LAYOUT` 容易空间错乱，少了 `AUDIO` 容易没有环境声/对白音效设计，少了 `CHARACTER ACTING` 容易表情动作僵。

### 保存 vs 重新生成，区别在哪

| | 「保存修改」 | 「按当前内容重新生成」 |
|---|---|---|
| 会不会调用视频模型 | **不会** | **会**（真的去生成这一镜，会产生调用） |
| 改的是什么 | 这一镜的**内容真源**（提示词、时长） | 先用当前内容生成新视频，然后**覆盖**这一镜原来的产物 |
| 什么时候用 | 先把想法改好，稍后统一跑；或只是修文案 | 确认内容没问题，立刻重做这一镜 |
| 会不会影响别的镜 | 不会 | 不会（只重做这一镜） |

**重新生成的实现方式（解释"为什么不会把好的文件弄坏"）**：

1. 先把新视频生成到一个**暂存目录**（不是直接覆盖正式文件）；
2. 对暂存文件做一次**媒体校验**（读出它的实际信息，确认是一个能用的视频）；
3. 校验通过才**改名覆盖**正式产物。

所以：生成失败 → 正式产物**原样不动**；校验不通过 → 会提示（原文）`生成的片段未通过校验：…`，正式产物同样不动。你永远不会得到一个"半截文件把好文件盖掉了"的结果。

### 改完之后，为什么下次要重新确认

这是**故意的**，也是自动模式省钱的关键机制：

- 每一次"会产生模型调用"的动作（开始生成、单镜重生成）都会先检查：**内容改动时间**是否晚于**最近一次确认时间**？
- 如果你改过任何一镜的提示词/时长，就一定晚于上次确认 → 程序会要求你**重新确认**，然后才继续。
- 于是"先确认一次，之后随意改改再点重生成"这条路**走不通**：每一次新的开销都在你的知情之下发生。
- 界面上，需要重新确认时不会偷偷继续跑，而是**回到确认卡**并**取消勾选**，需要你重新勾选后再点。

### 你可以做什么（典型工作流）

1. 先只跑一小段（例如 30 秒、约 6 镜）验证风格。
2. 看完成片，挑出问题镜（人物脸变了、动作怪、没有环境声）。
3. 对问题镜点「修改片段」：只改有问题的那一句/那一块。
4. 点「按当前内容重新生成」→ 出现确认要求 → 确认 → 只重跑这一镜。
5. 全部满意后回完成态点「收口合成成片」。

> 有一条省时间的经验：**先改内容再重生成**。直接点「重新生成」而不改内容，等于把同样的提示词再跑一遍。

## 12. 常见问题与排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 点「生成预览」没反应 / 提示要先确认 | 你点的是「开始生成」而没勾选确认框 | 勾选确认框后再点（提示原文：`请先勾选确认，再开始生成`） |
| 提示 `自动模式需要视频模型…请在模型设置中配置并设为默认视频 Provider 后重试` | 还没有配置视频模型，或没有把它设为默认 | 到模型设置里配置一个视频类模型并设为默认，然后重试 |
| 提示 `已有自动模式任务在运行，请等待其完成或停止后重试` | 同时只允许一个自动任务（单飞） | 等当前任务跑完，或点 **「停止生成」** 让它尽快收口（批间生效）后再开始新的 |
| 任务跑太久，想先停下 | 不需要它继续了 | 点 **「停止生成」**：当前批跑完即止，未开始的批保持待跑，之后随时点「开始生成」从断点继续（章节 9） |
| 提示 `计划已过期，请重新生成预览` / `该计划已被消费，请重新生成预览` | 计划超过 24 小时；或这份计划已经用来启动过一次 | 点「生成预览」拿一份新计划 |
| 提示 `计划不存在或已损坏，请重新生成预览` | 计划文件缺失或被破坏（程序按"宁可拒跑"处理） | 重新生成预览 |
| 提示 `计划归属与任务 ID 不一致` | 计划与任务 ID 对不上（异常情况） | 重新生成预览；若反复出现请反馈 |
| 提示 `同名任务已存在且不是同一份计划；如需覆盖请显式确认（旧一轮将归档保留）` / `同名任务来自另一份计划；如需覆盖请显式确认（旧一轮将归档保留）` | 同名任务已经存在，而这次是另一份计划 | 确认卡上会出现 **「覆盖同名任务」勾选框**：确要替换就勾选它再点「开始生成」（旧一轮产物与确认历史归档保留）；不想动既有任务就重新生成预览（会拿到新的任务 ID） |
| 提示 `计划内含越出受控媒体根的参考图路径（N 条），已拒绝启动` | 计划里的参考图路径不在受控目录内（安全防线触发） | 删掉并重新添加参考图，然后重新生成预览 |
| 提示 `还有 N 个分镜未完成，请先重新生成失败片段再收口合成` | 有镜没成功，收口被前置拦下 | 在逐镜表里对失败的镜点「重新生成」 |
| 某镜一直是 `失败` | 该镜的生成被 Provider 拒绝/超时 | 看「失败原因」列；改一下提示词再重生成，或稍后重试（可只重跑这一镜） |
| 参考图"没生效" | ①文案里没出现该角色名（命中才注入）②Provider 不支持参考图（确认卡会有 W1）③角色超过 4 个，后面的没进槽位 | ①把角色名写进文案或调整命名 ②换 Provider ③精简角色数量 |
| 成片时长和我说的"大概"不一样 | 时长是按"单镜秒数 × 镜数"算的，只能落在离散点上 | 看确认卡上的 W3 与时长对比；调单镜时长或大概时长后重新生成预览 |
| 提示 `仅支持 PNG / JPEG / WEBP 格式参考图` | 选的文件其实不是这三种图片（改了后缀也不行，程序看文件头） | 换成真正的 PNG/JPEG/WEBP |
| 提示 `参考图不能超过 10MB` | 图片太大 | 压缩后再上传 |
| 提示 `参考图最多 8 张` | 达到了数量上限 | 先移除一张再加 |
| 关掉页面/切走，任务还在吗？ | 在跑。任务在主程序里执行 | 回到页面即可看到进度；**关掉应用再打开也没关系**——自动标签会自动挂回上次的任务（见章节 9） |
| 合成完成但没看到预览 | 事件丢失或还没返回路径 | 等几秒（界面每 3 秒兜底查询一次）；仍不出现在错误条上会给出原因 |
| 提示 `未授权的调用来源` | 有外部页面尝试调用受保护接口（安全拦截） | 属正常拦截；若在正常操作中出现，请反馈 |
| 提示 `没有可用模板分镜（film-kit 未加载或为空）` | 随包的分镜模板库没加载成功 | 检查安装完整性后重试；若持续出现请反馈 |

## 13. 费用与时长预期

### 确认是"清单式"，不是"金额式"

自动模式的确认卡**不显示金额**。原因是本产品里没有一个可信的视频单价表，写出一个假数字比不写更危险。取而代之的是**把要发生的事说清楚**：

> 我已知悉：将生成 12 个分镜（约 60 秒成片），确认后才会开始调用视频模型

你要判断的是：**镜数、时长、Provider、有没有降级（W1）、要跑多久（W5）**。

### 费用发生的四个时点

| 时点 | 会不会产生调用 | 说明 |
|---|---|---|
| 生成预览 | **不会** | 只做文本分析、提示词组装、估算 |
| 开始生成（首次） | **会** | 一次确认覆盖**整批**（例如 12 镜分 2 批，也是一次确认） |
| 单镜「重新生成」 | **会** | 每次都要求处于"已确认"状态；改过内容就必须重新确认 |
| 收口合成 | **不会**（不产生新的生成调用） | 只把已有片段拼起来 |

### 时长预期

- 程序内部按**每镜约 5 分钟**做墙钟预估；超过 2 小时会给你 **W5**。这个预估的数值**确认卡上直接显示**（字段名「预计耗时」，不足 1 小时显示分钟、达到 1 小时显示小时）。
- 逐镜生成是**并发 2 路**推进的（同时最多 2 个镜头在生成），所以总时长大致是「镜数 ÷ 2 × 单镜耗时」，而不是「镜数 × 单镜耗时」。W5 的估算偏保守，是刻意留的余量。
- 分批（**W2**）只是把执行切成每 10 镜一批顺序推进，**不需要你逐批点确认**。
- 参考数据：12 镜（60 秒成片）通常在数十分钟量级；120 镜会明显更久，建议分批推进。

### 磁盘预期

每个镜头的视频按约 **8MB** 估算。所以：

| 镜数 | 粗略磁盘占用 |
|---|---|
| 12 | 约 96MB |
| 60 | 约 480MB |
| 120 | 约 960MB |

确认卡上的「预计占用磁盘」就是按这个口径直接算给你看的（不足 1GB 显示 `MB`，达到 1GB 显示 `GB`；每镜按 8MB）。

（这是估算值，实际取决于分辨率与码率。）

## 14. 数据放在哪里、能不能清理

### 目录结构（占位符表示程序决定的根目录）

```
<媒体根>/film-engineering/
├── references/                     参考图受控目录（通过校验的参考图都在这里）
└── auto/
    ├── _plans/
    │   ├── <计划ID>.json           计划：包含这次要生成的每一镜的完整提示词
    │   └── <计划ID>.consumed       消费标记（这份计划已经用过一次）
    └── <任务ID>/
        ├── project.json            ★内容真源：每一镜的提示词 / 参考图 / 时长 / 状态 / 产物路径
        │                            以及确认历史、调用计数
        ├── ledger.json             执行记录：分批情况、每批状态、每镜状态
        ├── b0/ b1/ …               批次目录，里面是 shot_000.mp4、shot_001.mp4 …
        ├── .regen/                 单镜重生成的暂存目录（校验通过才会覆盖正式产物）
        └── archive/<旧轮次>/        若发生过"覆盖重跑"，旧一轮的项目与执行记录会归档在这里
```

### 三份"记录"谁是准的（冲突时的优先级）

**磁盘上的视频文件** > **ledger.json（执行记录）** > **project.json 里的状态字段**。

注意一个例外：**提示词、参考图、时长这些"内容"永远以 `project.json` 为准**——它就是你在片段编辑里改的东西的落点。

### 能不能清理

| 你想清理的 | 怎么做 | 注意 |
|---|---|---|
| 成片（最终视频） | 用「另存为」保存到你自己的位置；媒体根里的中间产物可交由应用的缓存清理功能处理 | 清理后无法从应用内再打开该任务 |
| 参考图 | 在界面里「移除」，或清理媒体目录 | 移除后若重新生成预览，需要重新添加 |
| 某个任务的全部中间产物 | 删除该任务目录（`<媒体根>/film-engineering/auto/<任务ID>/`） | 删了就再也无法从界面续跑或重生成该任务 |
| 应用整体临时缓存 | 使用设置里的缓存清理功能（会一并清理影视工程的临时目录） | 会清掉所有影视工程任务的中间产物，请先另存成片 |

> 提示：**先另存成片，再清理中间产物**。中间产物（每一镜的 mp4）是可以重新生成的，成片不一定能"无损复原"为同样的结果。

## 15. 能力边界与已知限制

这一节是**如实交代**，不是免责声明。写在这里的都是本文档核对代码后确认的当前状态。

| # | 限制 | 具体表现 | 影响与替代做法 |
|---|---|---|---|
| 1 | **「停止」是批间生效，不是立即中断** | 点「停止生成」后，当前正在跑的那一批（最多 10 镜）仍会跑完；这是刻意设计（半途掐断的批次无法保证产物完整） | 想早点停就早点按；未开始的批次保持待跑，停下后可随时继续 |
| 2 | **角色槽位只有 4 个** | 检出的第 5 个及之后的角色不会被映射进提示词 | 精简人物；或把次要角色写进描述里而不作为独立角色 |
| 3 | **逐镜状态不会显示"生成中"** | 状态只有 `待生成` / `已完成` / `失败`（`生成中` 是保留值，界面文案里有但实际不写入） | 看进度条与 `已完成 x / y 镜` 摘要判断整体进度即可 |
| 4 | **续跑恢复出来的确认卡只有概况** | 界面自动挂回上次任务时，确认卡显示任务 ID / 分镜数 / 批次 / 时长 / 方向 / Provider，**不显示逐镜一览、警告清单与磁盘/耗时预估**（这些来自规划阶段的服务端预览，续跑时不会重算） | 看逐镜细节请用逐镜表（运行态与完成态都有）；磁盘与耗时量级参考章节 13 的经验值 |
| 5 | **没有金额预检** | 确认卡是清单式（镜数 / 时长 / Provider / 磁盘 / 耗时），不显示任何金额 | 刻意如此：本产品没有可信的视频单价表，写一个假数字比不写更危险。请按你自己的模型计费口径判断 |
| 6 | **参考图的 10MB 限制没有在选文件前预检** | 界面不会在你选文件时先拦一次，而是上传后由服务端拒绝并弹错 | 选文件时留意大小即可 |
| 7 | **剧本超长只在"字数显示"与"按钮禁用"上体现** | 没有额外的长文本编辑辅助 | 超过 10000 字时先拆分；或把长篇切成分次任务 |
| 8 | **参考图能力取决于 Provider** | 当前 Provider 不支持参考图输入时，这些镜会降级为纯文本出镜（确认卡给 W1），不会报错 | 想要人物一致性就换成支持参考图输入的 Provider |

## 16. 术语表

| 术语 | 含义 |
|---|---|
| **分镜 / 镜** | 成片的最小单位。一个分镜对应一段连续画面（默认 5 秒），也对应一条完整的提示词 |
| **剧本 / 文案** | 你粘贴进去的原始文字 |
| **分场** | 把剧本按空行（以及场景标题行）切成"场"。场决定场景参考图怎么轮转，以及时间轴上的连续性 |
| **提示词** | 发给视频模型的完整指令文本。自动模式里它由模板 + 你的这段文案 + 角色映射组装而成，含下面这些结构块 |
| **GEO 空间布局** | 提示词块之一：把人物、道具、背景在画面里的空间关系写清楚（谁在左、谁在右、镜头在哪），用于保证跨镜的空间一致性 |
| **动作时间线** | 提示词块之一：把这几秒内"第 0–2 秒发生什么、第 2–5 秒发生什么"写清楚，用于保证动作连贯 |
| **音效 / AUDIO 块** | 提示词块之一：环境声、对白、音效的设计 |
| **角色表演（CHARACTER ACTING）** | 提示词块之一：这一镜里角色的情绪与表演要求 |
| **正向约束（POSITIVE CONSTRAINTS）** | 提示词块之一：画质与风格上的正向要求（例如 8K、无闪烁） |
| **角色槽位** | 提示词模板里预留的 4 个角色位置：`ROKO`、`JAXX`、`LULU`、`REIN`。程序把你检出的角色名按出现次数填进这几个位置 |
| **参考图绑定** | 决定"哪一张参考图注入到哪一个分镜"的过程：人物图按角色名命中、场景图按场轮转共享 |
| **Provider（视频 Provider）** | 实际执行视频生成的模型来源（在模型设置里配置并设为默认） |
| **批次 / 分批** | 执行时的分组，每批最多 10 镜，顺序推进；只影响执行节奏，不影响你的操作 |
| **账本 / 台账（ledger）** | 记录每一批、每一镜执行情况的文件，是"执行到哪了"的权威记录 |
| **收口** | "把清单收齐"的意思：确认每一镜都真的存在于磁盘上，然后才能合成 |
| **收口合成** | 把已经生成好的片段按顺序拼成最终成片（不产生新的视频生成调用） |
| **续跑** | 再次启动同一个任务时，程序核对磁盘，跳过已经生成的镜头，只补缺的 |
| **原文直送** | 影视工程的硬合同：你写的提示词**逐字符**发给模型，中间不做任何润色或"优化"改写 |
| **归档轮次** | 当发生"覆盖同名任务"时，旧一轮的项目文件与执行记录会被移进归档目录，保留审计痕迹 |
