# ADR-2026-09-01 架构重构决策点裁决

**日期**：2026-09-01
**状态**：Accepted
**依据**：`01-docs/架构重构/最终重构方案-2026-09-01.md` §2.8 决策点

本 ADR 记录架构重构方案中 4 个决策点的最终裁决，作为后续全部实施工作的决策基线。

***

## D1. ops-center 最终归属（拆独立仓库 vs 纳入 workspace vs 维持+契约）

### 决策

**先不拆**。立即执行方案 2.4.3 前两步（安全契约 + 独立 CI），第三步"拆仓与否"延后 6 个月，用真实跨端变更频率数据决策。

### 依据

- 方案 A 论证拆独立仓库的理由（零 workspace 依赖、仅 2 个 HTTP 端点耦合、自带 systemd+nginx 部署、发版节奏不匹配）成立，但方案 A 给出的拆仓判据是**跨端需求频率**。

- 实测证据：`feature_flags`、`pipelineOptions` 已是跨端需求第 2 例，趋势在加速。拆仓后高频跨端改动需双仓双提交，成本反升。

- 期间以"契约包（OpenAPI）+ 独立 CI（pytest+build）"维持"逻辑独立、物理同仓"。

### 后续触发条件

- 跨端运营需求 ≥ 每月 1 次 → 倾向不拆（维持现状）

- < 每季度 1 次 → 拆独立仓库

***

## D2. Windows 代码签名

### 决策

**暂缓**。记录为成本/风险权衡决策。保留 `latest.yml` SHA-512 + HTTPS 完整性校验作为发布通道完整性保障。

### 依据

- `apps/desktop/package.json:159-161` 已显式关闭签名；当前为个人分发形态，Authenticode 证书采购与受保护 release workflow 的成本高于收益。

- 若未来转公开分发（需要 Windows SmartScreen 免警告），再立项上 Authenticode + 受保护 release workflow，并作为独立 ADR 决策。

***

## D3. `stealth-preload.js` 反检测

### 决策

**做成用户可关闭开关 + 首次使用明确告知 + 平台 ToS 评估**。此项属业务合规风险（方案 A·S-12），非代码缺陷。

### 实施要求

1. 设置页新增开关（默认开启），关闭后不再加载 stealth 反检测逻辑。
2. 首次使用 stealth 功能时弹窗明确告知"该功能可能与平台服务条款冲突，仅供合规场景使用"。
3. 平台 ToS 评估结论记录到 `01-docs/learnings.md`。
4. 开关状态持久化，注销/重启后保持。

***

## D4. Stage -1 止血顺序确认

### 决策

按优先级执行：**-1.1 → -1.2 → -1.3 → -1.6（硬时限提前）→ -1.4 → -1.5 → -1.7 → -1.8**

### 依据

- -1.1/-1.2/-1.3 是"线上真实可利用"（静态凭据落盘 + 同机进程可读 argv），最高优先。

- -1.6（runtime bootstrap 验签）有 **pipelineOptions feature 分支合入 main 前的硬时限**，必须在该分支合并前完成，故其实际优先级高于 -1.4/-1.5。

- -1.4/-1.5 是低成本鉴权补漏。

- -1.7/-1.8 随 ops-center 第一批改动搭车。
