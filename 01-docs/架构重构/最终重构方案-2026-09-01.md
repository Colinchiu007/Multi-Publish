## 1. 总体策略：双引擎

> **债务熔断（机制） × 契约先行（路线）**

- **债务熔断**：用 CI 强制阻止架构债务继续增长——6 项指标量化基线，超阈值即阻断 merge。
- **契约先行**：按"绞杀者式模块化重构"推进——先立契约与单一事实源，再在兼容 facade 后移动实现；结构调整与行为变化分开交付。

不重写、不拆微服务。采用渐进式模块化重构。

## 2. 阶段性路线（Stage -1 → 4）

| Stage | 名称 | 内容 | 窗口 |
|---|---|---|---|
| **-1** | 安全止血 | 堵住可利用的凭据/密钥泄漏，先于一切 | 本周启动 |
| **0** | 护栏与基线 | 债务熔断 CI + 存量基线登记 + 产物清理 + channel inventory | 第 1-2 周 |
| **1** | 契约与枢纽 | IPC manifest + AdapterRegistry 接线 + domain 抽取 + 容器守卫 | 第 3-6 周 |
| **2** | 域收敛 | story2video 单源 + 发布能力模型 + ops-center 三步走 + 数据所有权 | 第 6-14 周 |

| **4+** | 数据触发优化 | 仅当指标恶化才做（sql.js 替换 / OTLP / 远程化，无期限承诺） | 持续 |

## 7. 质量与交付门禁

- 每个重大改动：隔离 worktree → 开发 → 测试 → **CCG 外部评审** → 提交/推送 → **PR + CI** → 合并回 main。
- 不允许在共享 main 上直接修改运行时代码（docs-only 除外，保持可回滚）。
- 重构完成后补全 PRD 与相关文档（架构、learnings、CHANGELOG）。
