## 一、给运营：30 秒上手

| 我想做的事 | 去哪里 |
|-----------|--------|
| 加一个内容类别（如「汽车」） | 运营中心 → **内容类别管理** → 新增类别 |
| 把「科技」改名成「科技前沿」 | 运营中心 → **内容类别管理** → 编辑 → 改「名称」 |
| 暂时不想让某类别出现在桌面端 | 运营中心 → **内容类别管理** → 关掉该行「启用」开关 |
| 调整类别在桌面端的显示顺序 | 运营中心 → **内容类别管理** → 用 ⤒ ↑ ↓ ⤓ 拖动 |
| 删掉一个自己加错的类别 | 运营中心 → **内容类别管理** → 删除（**内置的 10 类删不掉**） |

**改完什么时候生效？** 配置随运行时 bootstrap 下发到桌面端，桌面端**下次启动时**生效。
（不需要运营在运营中心手动推送任何东西，系统也不提供服务端推送入口。）

## 二、给桌面端用户：三处怎么用

### 2.1 热门选题

- 顶部分类 chip 的**名称与顺序来自运营中心**配置。
- 运营**停用**某个类别后，该 chip 不再出现；已经抓到的条目本身保留。
- 运营**新增**的自定义类别不会自动出现在抓取结果里 —— 详见 §三「为什么」。

### 2.2 账号分组

分组有两套维度，语义不同：

| 字段 | 含义 | 影响成员资格吗 |
|------|------|---------------|
| 平台筛选 | 这个组只装某个平台的账号 | **是**（硬筛选） |
| 类别标签 | 这个组的内容定位（如「科技」） | **否**（软标签） |

操作：
- 新建分组时可同时选类别标签
- 分组卡片上「编辑标签」→ 多选弹窗 → 保存
- 左侧栏可按类别筛选分组

### 2.3 采集库

- 采集条目卡片显示类别 chips
- 点「编辑标签」批量设置（最多 5 个）
- 顶部「类别筛选」：全部 / 未分类 / 各类别
- 打过标签的内容导出到爆款库时，标签会一起带过去

## 三、关键取舍（为什么这样设计）

### 3.1 为什么运营新增的类别不会自动进入抓取结果

抓取侧分类靠**关键词规则**（`classifier.js` 里的 `KEYWORD_RULES`），这是代码内资产。
如果让运营自由新增分类，就会造出「有分类名、但没有任何关键词规则」的类别 —— 结果永远是空分类。

所以：**运营能动态改的是「名称 / 排序 / 启停」**，不是「分类能力」。
自定义类别的实际用途是**给采集内容和账号分组打标签**，这是它真正的价值。

### 3.2 为什么运营中心没配过时桌面端不会变成「零分类」

内容类别是**展示资产**，不是权限边界。
如果沿用 feature flag 的 fail-closed（读不到按关闭），运营没配过时热门选题会变零分类、采集库打不了标签、离线用户直接不可用。

所以这里刻意用 **fail-open**：没下发 / 空 / 结构非法 → 一律回退内置 10 类（综合/社会/财经/科技/娱乐/体育/情感/教育/健康/国际）。

> 一句判据：**缺失时用户失去的是「能力」还是「权限」？** 权限 → 宁可不给；能力 → 该给默认值。

### 3.3 为什么自动化任务不做「过期补跑」

任务是「采集 → 改写 → 发布」，副作用**外溢到第三方平台**。
开机补跑 N 条过期任务会把平台限流打满，用户还会看到一堆莫名其妙的发布记录。

注意区分两个概念：
- **启动触发** = 你显式配的一种触发器（`启动时`），你配了它才会跑
- **补跑过期定时任务** = 系统偷偷把没跑的定时任务补上 —— **不做**

### 3.4 为什么失败处理是「先重试，再按策略」

如果直接二选一，选了「中断」就意味着下一次网络抖动整批全挂。
但你选「中断」的本意是「不要产生半成品」，不是「一次抖动就放弃」。

所以顺序是：**先按 `maxRetries` 重试 → 重试耗尽 → 才按 `failurePolicy` 处理**。

## 四、数据校验规则（完整版）

### 4.1 内容类别（运营中心）

| 字段 | 规则 | 违反提示 |
|------|------|---------|
| 类别标识 | 必填；`^[a-z][a-z0-9_]{1,31}$`；不得与现有重复（含已停用） | 「类别标识只能由小写字母、数字、下划线组成，且以字母开头，长度 2-32」/「类别标识已存在」 |
| 名称 | 必填；trim 后 1–20 字符；不得与现有重复 | 「名称不能为空」/「名称不能超过 20 个字符」/「名称已存在」 |
| 排序值 | 非负整数；拒绝 bool | 「排序值必须是非负整数」 |
| 备注 | ≤200 字符 | 「备注不能超过 200 个字符」 |
| 删除 | 内置类拒绝 | 「内置类别不可删除，可改为禁用」 |
| 总数 | ≤ 50 | 「类别数量已达上限 50」 |

### 4.2 自动化任务

| 字段 | 规则 | 违反提示 |
|------|------|---------|
| 名称 | 必填；1–40 字符；不重复 | 「请填写任务名称」/「任务名称不能超过 40 个字符」/「任务名称已存在」 |
| 触发器 | 至少 1 个；≤ 5 个；同类型只能一个 | 「请至少选择一种触发方式」/「同一触发方式只能配置一次」 |
| 每天/每周时间 | `HH:mm`（24h） | 「时间格式应为 HH:mm」 |
| 每周的星期 | 1–7 整数；至少一个；去重排序 | 「请至少选择一个星期」 |
| 间隔 | 5–1440 整数（分钟） | 「间隔需在 5 到 1440 分钟之间」 |
| 任务总数 | ≤ 20 | 「自动化任务数量已达上限 20」 |
| 失败策略 | `skip`（默认）/ `abort`；非法值回落 `skip` | — |
| 重试次数 | 0–3 整数；非法值回落 0 | — |

### 4.3 采集条目类别标签

| 规则 | 行为 |
|------|------|
| 数量 ≤ 5 | 超出截断，记入 `dropped` |
| key 必须匹配 `^[a-z][a-z0-9_]{1,31}$` | 不匹配丢弃，记入 `dropped` |
| 去重 | 重复项合并 |
| 未知 key | **保留**，记入 `unknown`；渲染置灰 + 悬停说明「该类别已被删除，标签保留但不再参与筛选」；不参与筛选 |

## 七、自动化任务的运行时行为（用户最关心的三点）

### 7.1 能不能后台运行？会不会影响我当前操作？

**能后台跑，当前操作不受影响。**
任务在主进程执行：不占用渲染进程、不弹模态框、不阻塞任何页面。你可以继续在发布页、创作页正常操作。

**但代价不藏着：**
任务会占用**模型调用额度**和**浏览器资源**。如果你正在手动发布，自动化任务可能和你竞争平台的发布频率限制。
所以自动化页顶部有一条常驻提示把这件事说清楚 —— 不是"完全无副作用"，是"不打断你，但会分资源"。

### 7.2 任务失败了怎么通知我？说什么？

| 情况 | 形式 | 内容 |
|------|------|------|
| 任务终态失败 | 可点击通知（停留 6s，点击跳任务详情） | 标题「自动化任务失败：{任务名}」；内容含失败原因 + 当前策略说明 |
| 策略 `skip` | 同上 | 「…策略为『跳过继续』，已重试 N 次后放弃。」 |
| 策略 `abort` | 同上 | 「…策略为『中断』，失败后已停止后续步骤。」 |
| 连续成功 | **不通知** | 避免噪音把你训练成对通知无感 |
| 上次失败、本次成功 | 通知 | 「自动化任务已恢复：{任务名}」 |

首个失败原因会写进任务详情的「最近错误」字段，界面直接可见，不需要翻日志。

### 7.3 失败后是跳过继续，还是中断？

**你来定，每个任务单独配。** 三档组合：

1. **重试次数**（0–3）：失败后先重试几次，都失败才算真失败
2. **失败策略**
   - **跳过继续**（默认）：记录这一步失败，继续跑下一步，整轮终态是「部分失败」
   - **中断**：立刻停下，不再跑后续步骤，终态是「失败」
3. 界面会写明怎么选：
   - 跳过继续 → 适合批量采集发布（个别源挂掉不该让整批白跑）
   - 中断 → 适合有强依赖的流水线（失败后继续会产生半成品）

**还有一个刻意不做的：** 应用没开时错过的定时任务，**开机不补跑**。
因为任务是「采集→改写→发布」，有外部副作用 —— 开机一次性补跑一堆过期任务会把平台限流打满，你还会看到一堆莫名其妙的发布记录。
想让应用一打开就跑，请显式勾选「应用启动时」这个触发器，那是你明确授权的。
