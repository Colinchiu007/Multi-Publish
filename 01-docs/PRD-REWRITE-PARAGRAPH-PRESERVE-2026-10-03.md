> **变更类型**: 🐛 Bug 修复 + 📦 行为加固 | **PRD 版本**: v1.0 | **流程**: 质量节拍完整节拍（TDD 先红后绿 + QM-5 五步）
> **关联文档**: [PRD-REWRITE-ENGINE.md](./PRD-REWRITE-ENGINE.md)（改写引擎主 PRD）、[PRD-REWRITE-WORD-COUNT-CONTROL-2026-09-12.md](./PRD-REWRITE-WORD-COUNT-CONTROL-2026-09-12.md)（字数控制）、[PRD-REWRITE-PAGE-UI-2026-09-16.md](./PRD-REWRITE-PAGE-UI-2026-09-16.md)（改写页 UI）

## 一、问题定义

### 1.1 用户报告（原始输入）

> 现在改写后的文案文字，没有正常的分段，是一整篇就一段。是有 bug 还是这方面就没有处理。

### 1.2 直答

**是 bug，不是没处理**——提示词层早已要求分段（运营中心种子硬约束第 2 条「文案内部如需分段，使用空行分隔即可」自 2026-09-18 就已存在），且 LLM 确实遵守了；但**后处理把分段压平了**。去 AI 味后处理器 `AITasteRemover` 的 Pass 3（句长节奏修复）在检测到「3 句以上近似等长句」时，会把全文按终止标点切句、再统一重组，这一过程**丢弃全部换行**，导致：

1. LLM 按空行分段的正确输出，经引擎 `_postProcess` 后变成一整段；
2. 段尾标点一并丢失（切句时剥离标点、重组时统一补「。」，段尾无标点时什么都不补）。

### 1.3 影响面

| 项 | 说明 |
|---|---|
| 影响入口 | 桌面端改写页（`/rewrite`）、热门选题一键生成视频（改写引擎链路）——所有真实改写调用 |
| 触发条件 | 全部 5 个内置策略 `postProcess.removeAITaste: true`，真实改写必经 Pass 3；只要全文存在 3+ 连近似等长句（长度差 ≤20%）即触发压平 |
| 影响行为 | 多段文案压成一整段 + 段尾标点丢失 |
| 不影响 | 改写主流程成败、质量评估、知识库回写、发布链路（发布侧只透传文本） |

### 2.3 系统性漏洞（QM-5 ③）

**文件级**：`packages/rewrite-engine/src/ai-taste-remover.js` 的文本重组类 pass（Pass 3）从未定义「结构不变量」（段落/换行保留），结构破坏型副作用无任何机制盯防。

**机制级**（三个缺口，全部在本 PR 闭环）：
1. **无结构不变量**：重组型后处理没有「换行结构不变」的显式契约（本 PR 在代码注释 + PRD §4.1 双重落地）；
2. **无回归锁**：没有任何测试断言换行/分段在去 AI 味后保留（本 PR 补 5 例单元锁 + 3 例端到端锁）；
3. **无输出结构验证**：改写结果无「非单段」结构检查（登记为后续 UX 增强项，见 §十一.3）。

## 三、修复方案（双保险架构）

### 3.1 保底层（确定性）：后处理保留分段

**文件**：`packages/rewrite-engine/src/ai-taste-remover.js`

1. `_addHumanTexture()`：先按 `\n` 切分自然段 → 仅对**单个自然段**做句级重组 → `join('\n')` 原样回填换行。节奏检测 `_detectRhythm` 仍在全文层（语义不变），只有**合并动作**被限制到段内。
2. `splitSentencesWithPunct()`（新增函数）：切句时**保留每句终止标点**（`split(/([。！？；!?;]+)/g)` 捕获分组 + reduce 回填）；无终止标点的尾段原样返回、不追加标点。
3. `_mergeUniformSentences()`：切分换用 `splitSentencesWithPunct`；合并衔接点把前句终止标点改成逗号（`replace(/[。！？；!?;]+$/, '')` 后接「，」），后句保留原标点；重组 `join('')`（按原文标点回填，不再统一补「。」）。

**保底层设计判据（必须写清的边界）**：

| 判据 | 内容 |
|---|---|
| 切分单位 | `\n`（单换行与空行均原样保留；只改段内文本，不动换行符本身） |
| 合并范围 | 仅段内 3+ 连近似等长句（±20%）且相邻对长度和 <80 字（阈值不变，仅作用域从全文收窄到段内） |
| 标点契约 | 保留原文标点；合并处前句终止标点→逗号、后句原标点保留；段尾无标点不追加 |
| 失败模式 | 无新增：`split('\n').map().join('\n')` 对任何输入都输出同结构文本（纯函数、无异常路径） |

### 3.2 上游层（概率性）：LLM 输出侧分段约束

| 层 | 文件 | 改动 |
|---|---|---|
| 模式指令 | `rewrite-engine-core.js` `_getModeInstructions` | 三模式各追加第 6 条：「分段输出要求：按内容逻辑（imitate）/What-Why-How-So What 层次（expand）/大纲结构（create）划分自然段，段与段之间用空行分隔（抖音口播类短文案除外）」 |
| 引擎内置硬约束回退 | `rewrite-engine-core.js` `BUILTIN_DEFAULT_HARD_CONSTRAINTS` | 第 2 条升级为「文案内部如需分段，使用空行分隔即可；除口播快节奏短文案外，成品应有 2-5 个自然段，禁止整篇压成一段」 |
| 运营中心种子 | `ops-center/backend/services/rewrite_hard_constraint_service.py` `SEED_HARD_CONSTRAINTS` | `hard-constraint-default-v1` 第 2 条与引擎内置逐字同步；描述注明「2026-10-03 补空行分段要求」 |
| 桌面端 service | `apps/desktop/electron/services/rewrite-engine.js` | **零改动**（该层无自己的后处理；硬约束经 `setHardConstraints` 注入，种子内容升级后运行时自动生效） |

**例外定义**：「口播快节奏短文案」与内置策略 `strategy-douyin-viral`（抖音口播策略）对齐——口播稿追求节奏紧密，允许单段。引擎无法在确定性代码里判定「本篇是否口播」，因此该例外写进提示词由 LLM 按策略语境判断；**保底层不做例外判定**（结构不变量无例外：后处理永远保留输入结构，不主动合并段落，也不主动添加段落）。

## 六、功能逻辑

### 6.1 `_addHumanTexture` 新逻辑（伪代码）

```
_addHumanTexture(text):
  rhythm = _detectRhythm(text)          // 全文层检测，语义与阈值不变
  if rhythm.signal:
    paragraphs = text.split('\n')
    paragraphs = paragraphs.map(p => _mergeUniformSentences(p))   // 仅段内重组
    result = paragraphs.join('\n')      // 结构不变量：换行原样回填
  return result
```

### 6.2 `splitSentencesWithPunct` 规则表

| 输入片段 | 输出 |
|---|---|
| `A。B！C` | `['A。', 'B！', 'C']` |
| `A！！B` | `['A！！', 'B']`（连续标点按捕获组整体归前句；B 无标点保持无标点） |
| `ABC`（无标点） | `['ABC']` |
| `''`（空串） | `[]` |
| `A。  B。`（句间空白） | `['A。', 'B。']`（trim 归一） |

### 6.3 引擎侧契约变化（对调用方）

| 面 | 变化 |
|---|---|
| result 字段结构 | 不变（success/result/title/strategy/warnings/sensitiveHits/quality/viral/knowledgeRefs/metadata 全部不变） |
| result.result 内容 | 多段输出的换行结构从此保留（此前必然压平）；标点不再被统一改写为句号 |
| 调用方适配需求 | 无（文本内容改进，类型与字段零变化） |

## 十一、非目标（Explicit Non-Goals）

1. **不新增 UI**：改写页无新控件、无新提示；显示改进来自引擎侧文本。
2. **不新增 locale**：无 locale 键变更，不触发成对门禁。
3. **不做「单段检测告警」**（结果只有一段时提示用户）——登记为后续 UX 增强项（需 UX 决策 + locale 成对）。
4. **保底层不做口播例外判定**：结构不变量无例外——后处理永远保留输入结构；例外只存在于 LLM 输出侧（§3.2）。
5. **不处理「截断截在段中间」**：长度截断可能把最后一段截断（不新增换行）——属既有截断行为，未变更；「截断优先保留完整段落」登记为后续增强。

## 十二、风险与缓解

| 风险 | 缓解 |
|---|---|
| 段内合并衔接点标点行为变化（统一补句号 → 保留原标点） | R4/R5 锁定标点契约两侧；既有用例全绿证明无回归 |
| LLM 不遵守分段要求（概率性） | 上游层是概率性约束，保底层是确定性保障——即使 LLM 不分段，后处理也不再压平（根因已除）；多层提示（硬约束 + 模式指令）提高遵守率 |
