# Story2Video 字幕分句质量子 PRD

**状态**：已实现  
**适用模块**：视频创作 → 故事讲述（Story Telling）  
**关联技术规格**：[subtitle-split-quality](../openspec/specs/subtitle-split-quality/spec.md)

## 1. 背景与问题

Story2Video 会把场景文案切分为字幕块，并据此生成字幕时间轴和旁白对齐数据。若长度切分只按字符位置选择边界，字幕可能出现 `三国|志`、`看地|形`、`灭|亡` 等词内断裂；完成体“了”被误判为优先切点时，还可能出现 `杀了|人`、`完成了|任务`。

这类结果虽然保留了全部字符，却会降低字幕阅读自然度，也会让字幕块与旁白语义停顿不一致。

## 2. 产品目标

为 Story2Video 用户提供适合短视频阅读的字幕块：

- 优先保持中文词语、书名、引文和短语的完整。
- 保持字幕块与场景原文、旁白时间轴的连续对应关系。
- 在“长度上限”和“词语完整”冲突时，优先避免词内断裂；必要时允许保留稍长但语义完整的字幕块。
- 分词能力不可用或异常时，字幕流程仍应完成，不因可选能力故障而中断创作。

## 3. 用户可感知需求

### 3.1 词语与短语完整

相邻字幕块之间的边界不得落在已识别的完整词语或共享保护短语内部。至少应覆盖以下用户反馈类型：

- 专有名词或常用词：`三国志`、`灭亡`、`地形`、`蒙古`、`江南`、`包税人`。
- 书名和引文内容：如 `《朱蒙》` 及成对引号中的连续内容。
- 枚举短语：顿号连接的并列项在可读范围内保持整体，不产生孤立词尾。

用户不应看到 `三国|志`、`看地|形`、`灭|亡`、`蒙古|人` 这类词内断裂。

### 3.2 完成体“了”后的宾语保护

在没有标点、空白或明确从句引导的情况下，字幕不得优先在完成体“了”与普通汉字宾语之间切分。用户不应看到：

- `杀了|人`
- `完成了|任务`
- `写了|信`

真实标点、空白和明确的转折/从句边界仍可形成字幕边界，不能把所有“了”后的文本强行合并。

### 3.3 安全回退

当词边界判断能力缺失、初始化失败、词典不可用或运行时异常时：

- 字幕仍需尽可能完成切分。
- 显式保护短语、代理对、小数和“了”后宾语保护仍然有效。
- 找不到安全边界时，可以保留完整或稍长字幕块；不得按固定字符位置裸切。
- 不向用户展示分词器、词典或内部实现错误。

## 4. 适用边界

- 本需求只适用于 Story2Video 的场景字幕块、字幕时间轴和相关旁白对齐输入。
- 本需求不定义通用中文文章分句，也不承诺所有中文分词器对任意新词给出完全相同的结果。
- 场景边界仍由既有场景分句流程决定；本需求主要约束场景内部的字幕分页。
- 字幕时间轴仍以真实旁白时长为权威，分句质量不能破坏时间区间连续性。

## 5. 验收标准

### AC-1：词内不切

使用默认字幕长度配置处理包含专有名词、双字词、书名和引文的场景文案时，任何相邻字幕块边界都不得落在受保护词语内部，字幕块拼接后保留原文。

### AC-2：宾语不从“了”后脱离

处理 `杀了人`、`完成了任务`、`写了信` 等文本时，不得在 `了|人`、`了|任`、`了|信` 位置产生优先边界；遇到真实标点或明确从句引导时，仍允许自然切分。

### AC-3：字幕可读性优先

当所有长度范围内的候选边界都会劈开词语、短语或完成体宾语时，系统应选择更宽的安全边界或保留语义完整块，不得为了满足字符上限产生坏词。

### AC-4：三端结果一致

TypeScript 权威实现、Electron JavaScript 镜像和 Python sidecar 对同一文本及同一配置输出逐块一致，且共享回归向量覆盖用户反馈坏例。

### AC-5：异常可恢复

模拟词边界判断器缺失和运行时异常，字幕流程仍完成；输出不落在显式保护短语、代理对、小数 token 或“了”后普通宾语之间，且不向字幕调用方抛出未处理异常。

### AC-6：时间轴不回归

字幕块按原文顺序连续覆盖场景文本；生成的时间区间连续、互不重叠，首块从场景起点开始，末块在场景旁白结束处结束。
