# PRD：CI 失败信号的形态治理与 issue 台账口径（issue-archival-and-signal-hygiene，2026-10-05）

> 状态：已实施（随 #2878 / #2610 / #2635 / #907 处置落地）
> 范围：工程质量门禁与 issue 治理，**不含用户可见功能**。本文记录的是**契约**：信号长什么样、什么算已解决、什么只能封存。

---

## 1. 背景与问题定性

2026-10-05 全量分诊发现：仓库有 **787 张 open issue**，其中 **783 张是 `CI Failure Handler` 自动开出的 `ci-failure` 单**。

这带来两个具体危害：

1. **信号被淹没** —— 「现在还有哪些 CI 问题」无法从 issue 列表读出。#2458 原文的抱怨即此：「真实故障混在里面难以分辨」。
2. **键选错** —— 旧单的去重键是 **commit sha**，不是**成因**。同一成因在 `Electron CI` 名下有 126 张彼此等价的单，最严重的一类（Doc Sync Gate）有 137 张。

**关键定性：这不是「有 787 个问题」，而是「787 条历史记录 + 少量当前信号」。** 本 PRD 的全部设计围绕这一句。

---

## 2. 两种形态的识别与差异

| 维度 | 旧形态（per-commit） | 新形态（签名） |
|---|---|---|
| 标题 | `ci-failure-<40 位 commit sha>: <Workflow> 失败` | `ci-failure[<类别>] <Workflow>: <job> / <step>[ :: <测试文件>]` |
| 类别取值 | — | `test-failure` / `ci-failure` / `setup-failure` / `doc-sync-drift` |
| 去重键 | 提交 | 成因（工作流 + job + 步骤 + 测试文件） |
| 复发表现 | **永远开新单** | **在同一张单上追加评论** |
| 额外标签 | `legacy-per-commit` | 无 |
| 语义 | 某一次 push 上发生过一次失败 | 这条成因**当前是否还在复现** |
| 处置 | **封存**：打标签、保持 OPEN | 见 §4 结单判据 |

---

## 3. 封存口径（742 张存量）

- **动作**：统一打 `legacy-per-commit` 标签；**保持 OPEN**；不评论、不改正文
- **判定**：标题匹配 `/^ci-failure-[0-9a-f]{40}:/`
- **验收**：打标后逐张核对，**742/742、零漏打**
- **为什么不做折叠**：旧单键在 commit sha 上，让新签名去「匹配」它们只能任选一张挂复发记录 —— **那是把随机选择伪装成同因归并，比开着更坏**。诚实的收敛只有两条：按成因折叠（≈1500 次 API 调用；且 `run_attempt` 陷阱会让重跑过的 run 重算出错误签名），或封存。本 PRD 选后者。
- **为什么不 close**：关掉会销毁 2026-09 之前那段时间线的取证价值；且这些单与「当前 CI 是否健康」无关，打标签已足以在列表层面与真实信号分开。

### 3.1 批量打标的实现约定（tool）

| 约束 | 说明 |
|---|---|
| 单个 `labelableId` | `addLabelsToLabelable` 只接受**一个**，需用**别名**在同一 GraphQL 文档里发 N 个 mutation |
| 变量只能传标量 | `gh api graphql` 的 `-f/-F` 把 `[ID!]!` 喂 JSON 数组会被当成单个 ID 字符串 ⇒ **id 一律内联字面量** |
| 504 要退避 | 别名一多会返 **HTTP 504**，且返回 **HTML 错误页而非 JSON** ⇒ 重试 + 退避，批次 ≤ 10 |

## 4. 新形态的结单判据

**两条都成立才关**：

1. **该门禁当前是绿的** —— 取证来源用 REST `actions/runs?branch=main`，**不用** `gh run list --branch`（两者实测互相矛盾）
2. **同因未复发** —— 「最后一条评论距今超过 3 天」

### 4.1 为什么判据是「评论时间」而不是「是否 OPEN」

签名去重按**标题检索** ⇒ 同因复发表现为**在同一张单上追加评论**。

⇒ 「单子开着」完全不含信息量；唯一有效的存活信号是评论时间轴。

### 4.2 本轮分诊结果（2026-10-05）

| 处置 | 张数 | 判据 |
|---|---|---|
| 结单（comment + close） | 32 | 零评论，或最后评论 ≤ 2026-10-02 |
| **保持 OPEN** + 分诊评论 | 9 | 最后评论 ≥ 2026-10-03 ⇒ **仍在复发** |

**若按「开着 = 还活着」一刀切关闭，会把这 9 张真实复发信号一起埋掉。** 这是本 PRD 最重要的一条防线。

保持 OPEN 的 9 张里复发最密集的两条：`QG Changes / Detect docs-only changes`（15 条评论）、`Doc Sync Gate`（25 条评论）。

## 5. 测试期出站台账（#2878）

### 5.1 契约

`scripts/test-egress-ledger-baseline.json` 的清单**只能缩小**。残留 `blocked::` 条目分三类：

| 类别 | 例 | 处置 |
|---|---|---|
| 守卫自测 | `blocked::example.com:8099` | 常驻，删除等于拆掉自测 |
| 预期本地工具 | `child::ffmpeg.exe`、`child::git` | 常驻；新增命令名必须先说明它为什么会被真起 |
| **欠账（被测代码真的想出网）** | 已清零 | 补桩 → 删条目；**基线里不得再留「欠账」字样** |

2026-10-05 起基线**首次不含任何欠账条目**。

### 5.2 三条欠账的根因与「桩承重」判据

| 条目 | 根因 |
|---|---|
| `channels.weixin.qq.com:443` | 用例只桩了 `tryHttpLoginCheck`；`checkLoginStatus` 判有效**之后**还会调 `refreshProfileFromHttpApi`，该模块直接持有真实 checker 模块对象 |
| `mp.toutiao.com:443` | 同一形态的第二落点 |
| `ops.example.com:443` | **生产行为是有意的** best-effort 运行时下发；错的是旧注释与夹具 |

**「桩承重」的双重反证**：① 摘掉桩后测试变红（`Tests 1 failed | 82 passed`）② 出站台账重新记回原 host。只做 ① 不算。

### 5.3 必须记住的机制陷阱

消费方模块**只在首次 `require` 时求值** ⇒ 那一刻若注册表里还没有桩，它把真实依赖存进模块级 `const` 并终身持有。

⇒ 症状是**单跑 `vitest -t` 反而干净、整文件跑才复现**。绿灯来自加载顺序而非断言。

## 6. 基线类 JSON 的「单键手术」纪律（#2610）

| 纪律 | 理由 |
|---|---|
| `--update` 不可用 | 源码把不一致项塞进 `blockedRaise` 后 `continue`，**拒绝抬高已挂账项** |
| `--update --rewrite` 禁用 | 会按实况全量重生 96 个键、重排键序、掩盖别人的漂移 |
| 只能单行替换 | 文件是**纯 CRLF** 且**键不是字典序**；`JSON.stringify` 整体重排会造出巨量假 diff |
| 两口径对账 | `git diff --numstat` 与 `--ignore-cr-at-eol --numstat` 逐文件一致才收工 |
| 不顺手抬 | 登记值领先于实况时抬它是**无谓的基线 churn**（`Publish.vue` 实况 1734/登记 1730，余量 196 行，未动） |

### 6.1 现状与剩余空间（2026-10-05 实测）

| 文件 | 登记值 | 实况 | 净增 | 容差 200 剩余 | 本 PRD 处置 |
|---|---|---|---|---|---|
| `locales/zh.js` | **3709**（原 3552） | 3709 | 0 | 200 | 已对齐 |
| `locales/en.js` | **3709**（原 3552） | 3709 | 0 | 200 | 已对齐 |
| `Publish.vue` | 1730 | 1734 | +4 | 196 | **未动**（不需要） |

**未偿还的债（#2610 保持 OPEN）**：`locales` 仍应按功能域拆成多文件 + 聚合入口导出，且**必须让 Gate 7 的 zh/en 成对检查继续成立**。

## 7. 「门禁绿」不等于「审计跑过了」（#907）

`QG Autonomous` 的 `Gate 9` 步骤 conclusion = `success`，但：

```
AUTONOMOUS_GATE = PROMPT_REVIEW_REQUIRED      （不是 PASS）
verdict: NEED_HUMAN, score: 0, items: 0
##[warning]AUDIT_NO_VERDICT: ... green here does NOT mean coverage was audited.
```

**契约**：判一个 gate 的健康度必须同时看**步骤结论**与 **gate 状态变量**。

`agent-review-gate.js` 打出 `AUDIT_NO_VERDICT` 告警是**正确形态** —— 拒绝把「没判」当成「判过了」。本 PRD 认可该设计。

**#907 保持 OPEN**，且处置顺序需调整：原单把「修 FeatureDetector 提取噪音」列为治本，但它其实**排在第二**。`score: 0` 同时可能来自「LLM 端点不可用」与「提取噪音」，两者被同一指标掩盖 ⇒ **不先证伪端点就修 FeatureDetector 是在盲修**。

**禁止**调低 `--threshold=0.5`（掩盖真实覆盖率下降）。
