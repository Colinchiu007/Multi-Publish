## 一、这是什么

「去 AI 味」是文案改写功能内置的**后处理引擎**：AI 改写完成后，自动把结果里的 AI 痕迹（套路词汇、模板结构、机械句式）改写成更接近真人写作的表达。

**你不需要做任何事**——改写完成的同时它已经工作完了。但它有几个你可以感知和利用的行为，了解后能显著提升改写质量。

### 它具体做三件事

| 步骤 | 做什么 | 举例 |
|---|---|---|
| **杀 AI 词汇** | 把 AI 高频套话替换成人类表达（117 条内置词表） | 「综上所述」→「说到底」、「深入分析」→「细看」、「至关重要」→「很关键」 |
| **破 AI 结构** | 删掉 AI 味开场铺垫、修掉机械标点 | 「在当今社会，人们越来越…」开头直接被移除 |
| **句长节奏修复** | 连续等长的机械句合并成有长有短的自然节奏 | 三个 12 字句 → 一长一短 |
| **底线保护** | 常用词不过度替换（「首先/然而/此外」出现 3 次以上才动） | 正常文章不会被改得不像话 |

### 两层安全底线

1. **词表底线**：哪怕运营中心把词库清空，引擎内置的 117 条替换依然生效——去 AI 味永远不会「失效」；
2. **反注入护栏**：每次处理前后都对比 AI 痕迹计数，**改写后痕迹反而变多就整体回滚**——它永远不会「越改越 AI」。

## 二、改写页能感知到的三个信号

改写完成后的「改写结果」卡片顶部元信息行：

```
策略：故事化爆款策略    AI味等级：20%    原文 520 字 → 结果 860 字
```

| 显示项 | 含义 | 怎么用 |
|---|---|---|
| **策略** | 本次命中的改写策略（自动匹配或你手动选的） | 对结果不满意时，优先换策略重写而不是反复重试同策略 |
| **AI味等级：N%** | 结果中残留的 AI 痕迹浓度（0% = 干净） | 见下方判读表 |
| **字数变化** | 原文 → 结果（选题创作模式显示「主题 N 字」） | 字数控制建议配合设置区的「字数控制」输入框使用 |

### AI味等级判读参考

| 等级 | 判断 | 建议动作 |
|---|---|---|
| **0-15%** | 干净，接近人写 | 直接用 |
| **15-35%** | 有少量残留 | 通读一遍，重点看开头结尾——模板腔最爱藏的地方 |
| **>35%** | 痕迹明显 | 换一个改写策略重新生成；反复偏高说明原文题材本身套话多，先手动删掉原文里的 AI 套话再改写 |

> 注意：这个分数只衡量**文本风格**（像不像 AI 写的），与「改写质量评估」的充分度/原创性分数是两套体系，别混着看。

## 三、怎么影响去 AI 味效果（终端用户可用手段）

终端用户**没有**去 AI 味的开关或强度滑杆——它是自动运行的。但你有三个间接手段：

### 3.1 选对改写策略（影响最大）

设置区的「改写策略」：

- **自动匹配**：按目标平台/行业自动选策略，适合大多数场景；
- **手动选择**：五套策略（故事化爆款 / 电商转化 / 抖音口播 / 小红书种草 / 干货知识）各自带不同的风格指令与语气设定，去 AI 味的语气处理会跟随策略变化。

**经验**：抖音口播类短文案允许不分段、节奏更密，AI 味残留天然略高（这类文案本来就更「喊麦」）；干货知识类长文 AI 味残留通常最低。

### 3.2 用字数控制避免「注水味」

设置区「字数控制」填最小/最大值。不控制时短文被强行扩写容易出现空洞的过渡句（那是另一种「AI 味」，词表救不了）——**让字数贴近内容本身的自然长度**。

### 3.3 结果可编辑

结果区是可编辑文本框：改完不满意的地方可以直接手动调，然后「📋 复制 / 💾 存入草稿 / 🚀 去发布」都按你编辑后的文本走。

## 四、管理员：运营中心「去AI味词库」

> 入口：运营中心 → 左侧菜单「去AI味词库」（仅管理员可见）。

### 4.1 词库语义（必读）

- **叠加 + 键覆盖**：桌面端引擎内置 117 条词表是**安全底线**；词库里**同词目覆盖**内置替换方向，**新词目追加**为新的替换；
- **停用 = 禁用该词**：把某条词目停用（enabled=0）后，桌面端改写会**跳过这个词的替换**——包括内置词。例：停用「综上所述」后，改写结果会保留「综上所述」原样；
- **即时生效**：保存后随运行时配置下发到桌面端，正在使用的桌面端**下次改写即生效，无需重启**；
- **离线兜底**：桌面端从未收到词库（或清空）时自动回退内置词表，行为与升级前一致。

### 4.2 界面操作

| 操作 | 步骤 | 说明 |
|---|---|---|
| **查找** | 顶部搜索框输入词目/替换词（模糊匹配）+ 级别下拉（S1/S2/S3）+ 状态下拉（启用/停用） | 表头下方显示「共 N 条，当前显示 M 条」 |
| **新增** | 「新增词目」→ 填原词（≤30 字）、替换词（≤50 字）、级别、说明（可选）→ 保存 | 原词不能为纯标点或单个正则符号（如 `.`）；重复词目报 409 |
| **编辑** | 行内「编辑」→ 替换词/级别/说明可改，**原词只读**（主键） | 改词目本身 = 删除后新增 |
| **启停** | 行内开关直接切换 | 停用操作有二次确认（防止误触影响全部桌面端改写） |
| **删除** | 行内「删除」→ 确认 | 内置词删除后**回到内置替换方向**；新增词删除后不再替换 |
| **导出** | 「导出 JSON」→ 下载 `ai-taste-map-export-<日期>.json` | 含全部字段，可直接再导入 |
| **导入** | 「导入 JSON」→ 选择文件 → 确认条数 → 执行 | **整批原子**：任一条目非法整批拒绝（报第一条错误的行号与原因）；按原词幂等覆盖；单批 ≤500 条 |

### 4.3 词目字段规范

| 字段 | 限制 | 说明 |
|---|---|---|
| 原词（word） | ≤30 字；不能含换行/控制字符；不能是纯标点或单个正则符号 | 匹配时**大小写不敏感**（英文词目写一种大小写即可） |
| 替换词（replacement） | ≤50 字；不能含换行/控制字符 | 建议与原词语气一致，避免替换后句子不通顺 |
| 级别（severity） | S1 / S2 / S3 | S1 = AI 标志性结构词（单次出现即替换）；S2 = 常见 AI 词汇（密度驱动）；S3 = 英文风格偏好。级别影响「AI味等级」评分权重（S1 权重最高） |
| 说明 | ≤200 字 | 建议写明为什么加这条（哪个平台/哪类内容实测发现） |

### 4.4 运维建议

1. **别一口气停用大量内置词**：每条内置词都来自实测的 AI 痕迹样本；停用前先想清楚这条词在你业务的语境里是否真的是问题；
2. **新增词目先小范围验证**：加完后在桌面端实际改写一篇典型文案，确认替换后语句通顺，再继续加；
3. **用导出做备份**：重大调整前先导出一份 JSON；改坏了可以改回 JSON 重新导入（幂等覆盖）；
4. **「AI味等级」不是 KPI**：它反映文本风格浓度，不同题材基线不同——追求把所有文案都压到 0% 会伤害内容自然度。

## 五、强度参数（管理员，进阶）

去 AI 味的**处理强度**按改写策略配置（运营中心 → 改写策略 → 编辑策略 → postProcess JSON）：

```json
{ "removeAITaste": true, "aiTasteIntensity": 2, "sensitiveCheck": true, "maxLength": 2000 }
```

| 强度 | 行为 | 适用 |
|---|---|---|
| `1` | 只做词级替换（跳过句长节奏修复与口语化） | 句式需要严格保留原文节奏的场景 |
| `2` | **默认**。词级替换 + 破结构 + 句长节奏修复 | 绝大多数场景 |
| `3` | 在 2 的基础上追加口语化（「我们」→「咱」等） | 强人设、强口语的平台账号 |

- 字段不写或非法值 = 按 2 处理（完全向后兼容）；
- `removeAITaste: false` = 该策略**完全跳过**去 AI 味（连词表也不跑）——仅在确认该策略产出不需要去 AI 味时使用。

## 六、工作原理与生效机制（管理员进阶）

```
改写策略 postProcess（removeAITaste / aiTasteIntensity）
        │
AI 改写结果 → ① 杀 AI 词汇（内置 117 条 + 运营中心词库覆盖层 − 停用词）
            → ② 破 AI 结构（开场铺垫移除 + 标点修复）
            → ③ 句长节奏修复（仅段内，保留原文分段与标点）
            → 反注入护栏（痕迹变多则整体回滚）
        → AI味等级评分 → 结果返回
```

- **词库下发链**：运营中心保存 → runtime/bootstrap（Ed25519 签名保护）→ 桌面端本地持久化 → 引擎注入 → 下次改写生效；
- **分段保留承诺**：去 AI 味永远不会把改写结果的分段压平、不会丢句尾标点、不会把「！」改写成「。」（2026-10-04 修复的结构不变量，见 PRD-REWRITE-ENGINE §十四）；
- **词表遍历顺序确定**：同一篇结果重复处理输出完全一致（无随机性）。

## 七、常见问题（FAQ）

**Q1：改写结果里还有 AI 套话，词库为什么没替换？**
三查：① 该词是否在词库里被**停用**了（状态筛选「停用」看一下）；② 是否命中了**人类基线保护**——「首先/然而/此外」等常用词出现不足 3 次不会替换（这是特性不是 bug）；③ 该词是否大小写不同（英文条目匹配不区分大小写，词库登记一种即可）。

**Q2：我停用了一条词，桌面端还在替换？**
确认桌面端已重新同步过运营配置（重启应用或触发一次同步）；确认停用的是正确词目（原词完全一致，匹配不区分大小写）。

**Q3：替换后的词不通顺，想撤回这条替换怎么办？**
内置词：在词库里停用该条目（回内置替换方向）或把替换词改成更合适的表达；新增词：直接删除。

**Q4：能让某个策略完全不去 AI 味吗？**
能——把该策略的 `postProcess.removeAITaste` 设为 `false`（运营中心 → 改写策略 → 编辑）。但注意该策略的产出将保留 AI 原始风格。

**Q5：AI味等级每次都不同，是随机的吗？**
不是。同一输入完全确定（词表遍历顺序固定、无随机性）。不同是因为 LLM 每次生成的原文就不同。

**Q6：词库会影响「爆款库」「个人知识库」的改写吗？**
会——所有走改写引擎的链路（改写页、热门选题生成、爆款改写）统一经过去 AI 味后处理，词库全局生效。

**Q7：导入报「第 N 条非法」但那条看起来没问题？**
常见原因：词目里有不可见字符（从聊天工具/网页复制带出来的零宽字符）、尾部空格后被截断超长、severity 大小写写错（必须是 S1/S2/S3 大写）。用导出文件做模板修改。
