## Why

Story2Video 编排流水线当前已经由主进程以 autoAdvance + background 异步推进，但 renderer 仍把“是否后台运行”表现为一个需要用户主动点击的前台脱离动作。用户启动流水线后如果没有点击【后台运行】，创作页会继续挂载运行态、持有轮询并显示运行控制；历史记录卡片点击【继续/从断点继续】也会把运行中的任务重新挂回创作页。

这造成了产品语义不一致：同一个 run 无论用户是否点击按钮，主进程都在后台执行并占用并发槽位，但 UI 仍让用户以为存在“前台运行”和“后台运行”两种执行模式。本 change 将后台运行定义为所有运行中编排 run 的默认语义，减少用户操作，并让历史任务卡片成为运行中任务的稳定观察入口。

## What Changes

- 编排流水线成功启动并进入 running 后，renderer 自动释放运行态，不再等待用户点击【后台运行】；主进程 run 继续执行并占用并发槽位。
- 历史记录卡片点击【继续/从断点继续】后，若恢复结果进入 running，任务留在后台运行，不跳回创作页、不重新建立 renderer 轮询；历史列表刷新并显示运行中阶段进度。
- 移除已经没有控制意义的【后台运行】按钮及其“点击按钮才转后台”的交互契约。
- 运行中任务在历史记录中明确显示为后台运行，并提供阶段进度、更新时间和运行中提示。
- 分镜素材自选等需要人工输入的暂停检查点保留交互式恢复：恢复结果为 paused 时进入素材选择面板；该例外不是后台运行中的 run。
- 保留主进程的并发门禁、run 持久化、取消和错误处理；后台语义不释放槽位，也不改变真实 provider 行为。

## Scope

本 change 只覆盖 Story2Video/编排流水线的 renderer 运行态与历史卡片交互。非编排旧流水线、主进程并发算法、第三方 provider、账号登录和发布流程不在本次范围内。
