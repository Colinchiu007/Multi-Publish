## Context

见 proposal.md - Why。这里只补实现层面必须知道的两件事：

- **观测点在哪**：真实自检用假 adapter 驱动 N 个受管调用，并发数是在任务体内 `+1 / 完成回调里 −1` 计出来的（`apps/desktop/electron/services/rate-limit-self-check.js:62-85`）。因此「执行中」的边界是**回调是否跑过**，不是工作是否真在做。
- **两侧本来就不同源**：模拟器是离散事件模型，时间只在选择器/槽位/冷却处推进，不存在回调推迟；真实侧是挂钟。规格已承认挂钟耗时的不确定性（给了容差），本次是把同一承认扩展到由挂钟派生的并发计数。

实测数据（本机，`inject-429` 组：rpm=120 ⇒ 相邻起始间隔 500ms，单次调用 20ms，上限 2）：

| 条件 | 真实侧 max_concurrent_observed | 说明 |
| --- | --- | --- |
| 空载，同进程连跑 24 次 | 全为 1 | 时间线 0/512/1002/1511/2014/2670，严格串行 |
| vitest 内跑完整六组 | 全为 1，六组 pass | 说明与测试框架无关 |
| 12 个独立 CPU 压力进程 | 仍为 1，耗时只漂 18ms | 独立进程不饿本进程事件帧 ⇒ 排除「CPU 忙」这种含糊解释 |
| 同进程内阻塞 40ms / 每 250ms | 仍为 1 | 低于阈值不翻 ⇒ 判据不是「有点抖」 |
| 同进程内阻塞 600ms / 每 300ms | **全为 2**，且 2 ≤ 上限 2 | 时间线出现 `started=0 finished=600`：20ms 调用被记成 600ms，正是回调被推迟的直接证据 |

阈值行为与机制预测一致：**只有阻塞时长跨过相邻起始间隔（≈500ms）才会重叠**。这是「可证伪的机制」，不是猜测。

复发率（决定处置方式，也是「不能只靠重跑一次」的依据）：`electron-tests` 的串行单测步骤 `if: github.event_name != 'pull_request'` ⇒ 只有 main push / dispatch 真跑本用例。2026-09-28 单日最近 100 次 run 中 `event=push` 24 次、完成且成功 18 次、红 1 次 ⇒ ≈1/18。**因此本 change 的主证据必须是 3.1 那条能主动制造重叠的机制回归锁；观察若干次 main push 变绿只能算旁证，不足以证明修好了**（5% 事件跑一两次不红毫无信息量）。

## Goals / Non-Goals

Goals：
- 让对拍的并发判据与本仓产品侧已有的判据（自检第 133 行 `max_concurrent_observed ≤ maxConcurrent`）口径一致，消除「同一份代码两种契约」。
- 保持检测力：越上限、反向偏差必须红。
- 把「为什么允许 +1」变成可执行证据（阈值两档锁），而不是注释。

Non-Goals：
- 不改 governor 的调度/准入行为，也不改模拟器的离散模型（规格明写「不得改变调度行为」）。
- 不动 `durationTolerance` 口径（其「下限 + 比例」已有两轮 CI 实测依据）。
- 不把 `inject-429` 降级进 `KNOWN_DIFF_CASES`（那等于退出判定）。

## Decisions

**D1：判据取「夹在模型与上限之间」而不是「加常量容差」。**
采用 `real ≤ simulated + 1 && real ≤ maxConcurrent`，且 `real < simulated` 判红。
备选 ①「只断言 `real ≤ maxConcurrent`」：丢掉与模型的对照，模拟器若整体偏悲观就再也抓不到 ⇒ 否。
备选 ②「把并发也纳入比例容差」：并发是小整数，比例无意义，且会把 +2 也放过 ⇒ 否。
夹住上限这条让 `maxConcurrent=1` 的用例（`rpm30-concurrency1`）自动退化为严格相等——不是特例分支，是同一条判据的后果，这一点必须有测试锁住。

**D2：不做「免疫版度量」。**
曾考虑改从 governor 内部槽位占用取数。否掉：槽位的释放同样由任务 promise 结算驱动，饥饿下 governor 自己也认为两个槽被占（前一个的释放回调没跑），所以不存在「更真的 1」可取；改取数点只会把同一个挂钟事实换个地方读。备选②「用 `started+duration` 推算结束时刻」：那是把被测对象换成被模拟对象，对拍就失去意义 ⇒ 否。

**D3：噪声成立条件用可控饥饿做两档回归锁。**
在同进程内注入同步阻塞，分「远低于阈值（40ms）」与「跨过阈值（600ms）」两档，断言并发分别是模型值与模型值+1，且后者仍 ≤ 上限。
备选「只在 CI 抖动时人工认」：不可复现、不可回归 ⇒ 否。
风险是这类用例自身对机器敏感 ⇒ 断言只依赖「方向与是否越上限」，不断言具体总耗时。

**D4：命中噪声必须出声。**
判据走噪声豁免时，在结果对象里记 `noiseBypass` 并由测试打印，避免「豁免静默生效」变成下一个没人知道的兜底。

## Risks / Trade-offs

- [+1 豁免可能掩盖一次真实的轻度并发回归] → 上限夹住 + 方向限制 + `maxConcurrent=1` 用例严格化；并保留「不足阈值时 +1 必须红」的锁。
- [阈值用例在慢机器上两档都可能翻] → 两档都用「相对倍数」而非绝对毫秒表达（一档 ≤ 间隔的 1/10，一档 ≥ 间隔的 1.2 倍），并在每次运行打印实测阻塞时长与实际并发，便于事后判读。
- [规格放宽被误读为「测试不稳就调松」] → proposal/design 都写明判据来源是 24+ 次空载样本与两档阈值实验，不是单次抖动。

## Migration Plan

纯判定口径变更，无数据迁移、无接口变更。回滚 = 还原 `checks` 组装为相等断言（单点常量与一处判据函数）。
