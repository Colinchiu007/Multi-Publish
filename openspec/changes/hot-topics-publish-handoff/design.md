# Design — hot-topics-publish-handoff

## 1. 问题形状

链路 `热门选题 → 改写 → 存草稿 → 去发布 → 装载 → 提交` 中，**只有「装载」这一跳缺实现**：改写的产物（草稿）已经落库，发布页也已有成熟的按 id 装载能力（`loadDraft`）与批量条目能力（`articles[]` + `useBatchPublish`），缺的是把「N 条草稿」从 A 页传到 B 页，并让 B 页一次接住。

## 2. 方案对比

| 方案 | 做法 | 取舍 |
|------|------|------|
| A. 走 Pinia store 传交接载荷 | 热门选题写 store，发布页读取 | store 生命周期与「一次性交接」语义不匹配：需要清理时机、keep-alive 下容易读到陈旧载荷；且刷新/重进丢载荷。**否决** |
| B. 只传 `?draft=<第一条>` + 提示用户去草稿箱 | 最小改动 | 不解决「5 条要装载 5 次」，仍未兑现弹窗承诺。**否决** |
| C. 用 query 传 id 集合（`?drafts=`）+ 发布页装载为批量条目 | 交接幂等、可刷新可回溯（URL 即载荷） | URL 长度上限风险 → 以 50 条上限约束；query 是字符串 → 需要解析校验（本期实现）。**采用** |
| D. 直接跳发布页并自动提交发布 | 最省用户操作 | 未经用户确认即向真实平台发文，风险不可接受（尤其预置目标误选平台时）。**否决** |

## 3. 关键设计决策

### 3.1 为什么用 query 而不是 store

- **可刷新、可回溯**：URL 自带载荷，页面重载/重进仍能装载（草稿仍在主进程 store 时）。
- **一次性语义天然成立**：交接就是「跳转时的那一份 id 列表」，不需要额外的清理逻辑。
- **可测**：测试直接 push 路由即可构造现场（既有 `Publish.test.js` 的 keep-alive 用例同一套路）。

代价：id 集合进 URL，需要上限与解析校验（见 3.2）。

### 3.2 幂等键为什么是「id 串」而不是布尔

发布页被 `App.vue` 的 `<keep-alive :include="['Publish']">` 缓存，`onActivated` **每次激活**都会触发预填逻辑。用布尔「是否装载过」会出两种错：

- 记成 `true` 后，新一轮交接（不同 id）不再装载 → 用户看不到新内容；
- 每次激活都重置为可装载 → 用户切走再回来，编辑被回滚成草稿原文（静默丢编辑）。

以「本批已装载的 id 串」为键，同时满足：同批不重复装载、异批重新装载。

### 3.3 全部未命中为什么「不记账」

如果全未命中时也写入幂等键，那么用户在应用外删掉草稿、或换 profile 后，**即使回到选题页重新生成**（id 变了）都没问题，但若用户只是刷新页面重试（同一批 id），就会被幂等键挡住而永远装载不了。不记账的代价仅是「同一批 id 会再查一次草稿列表」，收益是失败可重试。

### 3.4 为什么账号必须与平台一起应用

`validatePublishTargets` 对每个 target 强制要求 `accountId` 非空（文案「请为<平台>选择至少一个账号」）。因此「批量工具条只勾平台」在提交阶段必然失败——工具条的价值为零。实现上由调用方构造 `{ platforms, accounts }`（accounts 取 `getDefaultAccount`），`applyTargetsToAll` 只负责写入；无账号的平台保持键缺失，让校验文案如实归因。

### 3.5 字段面为什么抽工厂

历史缺陷 `cover_*` 的形态是「有读点、无写点，恒为空」——新增字段只在一条路径上写了。装载路径与「添加文章」路径的默认字段面若各写一份，同样问题会重演且只在新条目上暴露。抽出 `createArticleItem()` 后，「新增字段」只需改一处，并由单测钉住两条路径键集一致。

### 3.6 交接后为什么预置全部可发布平台

热门选题入口的字面语义是「一键发布」，用户已经表达过「这些内容我要发出去」。若装载后还要用户手动勾 8 个平台 × 5 条条目（40 次点击），等于把「一键」退回「40 击」。预置 + 仍须手动点提交 + 逐条可改，是风险与效率的折中；该取舍已在 PRD §12.4 如实登记（存在误发到非预期平台的可能）。

### 3.7 向后兼容

- 单条仍走 `?draft=` → 单篇编辑器（既有语义零回归，既有用例继续通过）。
- 两个参数同时出现以 `?drafts=` 为准（新参数表示完整集合）。
- 视频去向未改。

## 4. 反证（mutation）设计

| 变异 | 操作 | 期望 |
|------|------|------|
| M1 | `HotTopics` 图文分支回到 `push({ path:'/publish', query:{} })` | HotTopics 新用例变红 |
| M2 | 禁用 `Publish` 的 `?drafts=` 交接分支（锚点 `if (handoffIds.length > 0) {` → `if (false) {`） | Publish 新用例变红（实测 4 例） |
| M3 | `applyTargetsToAll` 不写账号（`void ids`） | useBatchPublish 新用例变红（实测 2 例） |

已知弱项（如实登记）：M2 下「全部草稿不存在」用例仍为绿——该用例断言的是「不进入批量模式 + 条目为 0」，交接被整体禁用时该断言平凡成立。它对「装载空条目」这类变异有效，对「禁用交接」无效。因此 M2 的红由装载类用例提供（4 例）。
