## Context

See `proposal.md - Why`. 当前历史数据由项目列表和流水线运行记录合并，排序、筛选及卡片点击分别散落在父视图、子组件和一个尚未完全接管页面的 composable 中。新近合入的 `story2video-history-visibility` 保证 failed 任务可见，但其“未完成任务优先”排序规则需要由本 change 显式修订。

本次只改变 renderer 层展示与交互，不改变 Electron IPC、持久化格式、轮询周期、stale running 识别、恢复引擎或结果路由合同。locale 文件必须成对修改；Vue/CSS 变更必须有组件、路由和视觉证据。

## Goals / Non-Goals

**Goals:**

- 让父视图、历史组件与 composable 共享同一套可单测的时间校验、排序和精确筛选规则。
- 让卡片主体成为无副作用的详情入口，所有写操作保持显式。
- 以统一信息骨架承载各状态卡片，并为 paused/failed 增加本地化专项信息。
- 在不改变数据源的前提下兼容 camelCase、snake_case、ISO 与 epoch 历史数据。

**Non-Goals:**

- 不迁移或重写 PipelineEngine、项目服务或 IPC。
- 不改造旧的独立 `#/create/history` 路由；本 change 只覆盖视频创作页内嵌历史视图。
- 不把现有父组件历史状态整体重构进 composable。
- 不为缺失的旧数据编造模式、错误、耗时或阶段。

## Decisions

### 1. 用纯工具模块定义排序和筛选单一来源

新增 renderer 纯工具模块，集中实现候选时间字段、显式缺失/非法值校验、epoch/ISO 转换、确定性平局规则和精确状态筛选。父视图合并数据后调用排序，子组件的 computed 再次对筛选结果排序，composable 也复用同一函数。

选择该方案是因为轮询会替换数组内容，组件层必须能自行维持顺序；同时父层排序可保证其他消费者获得一致数据。备选方案是仅在 PipelineEngine 排序，但那会让 UI 依赖后端实现、无法覆盖本地项目合并后的顺序，并扩大 Electron 变更与打包门禁范围。

### 2. 时间解析先判缺失再解析

候选值先排除 `null`、`undefined`、空白字符串、布尔值与非有限数值，再分别解析有限 epoch 数值和日期字符串。所有候选缺失返回 `0`。平局先比较创建时间，再比较稳定身份字符串，最后保留输入序号作为重复身份数据的最终稳定兜底。

选择显式判空是为了避免 `new Date(null)` 被误当成 1970 年有效数据。备选方案是直接 `Date.parse`，但其对数值和部分非标准字符串的行为不够清晰，也无法表达缺失合同。

### 3. 状态标签由组件托管键盘行为，筛选值仍由父层控制

历史组件渲染固定六项 tablist，点击或键盘操作通过 `update:historyFilter` 更新父层。当前标签使用 roving tabindex；左右键循环，Home/End 跳到首尾。数量从完整 history 精确计算。

选择受控 prop/event 保留现有数据流，避免引入第二个筛选状态。备选方案是 Element Plus tabs，但本控件简单且已有专用历史样式，新增依赖式组件会增加视觉和键盘行为的不确定性。

### 4. 卡片主体只派发详情事件

非 cancelled 卡片具有 `button` 语义、`tabindex=0` 和 Enter/Space 处理，仅派发新的详情事件。所有动作按钮继续使用 `click.stop`；“打开结果”使用独立事件并沿用现有结果路由。详情采用当前页面内的模态层，显示选中任务的只读数据，并在具备资格时提供显式恢复/结果动作。

选择本地详情模态层可覆盖运行、暂停和失败等尚无持久项目页的任务。备选方案是把卡片点击统一导航到结果页，但没有 `projectId` 的运行记录无法满足该路由合同；继续沿用点击即恢复又违背无副作用详情要求。

### 5. 展示模型通过小型归一化辅助而非复制数据

组件按字段可用性渲染统一信息行，阶段名称复用 `getPipelineStage`，流水线名称复用 `getPipelineName`，状态/字段/动作全部走 `create.history.*` locale。暂停环境按已有数据字段优先级读取，已知值翻译，未知值回退原文；失败阶段和错误分别渲染。

不创建新的持久化 DTO，因为本次没有数据迁移需求。备选方案是加载时把所有记录深度映射成统一对象，但会复制原始任务并增加恢复/删除动作丢失身份字段的风险。

## Risks / Trade-offs

- [双层排序造成额外计算] → 历史列表规模有限，纯函数复制排序为 `O(n log n)`；用单测保证不修改输入数组。
- [旧任务字段形态不一致] → 所有可选字段先校验，未知值安全回退，缺失项不阻断详情。
- [卡片与操作按钮形成交互歧义] → 仅卡片 body 使用 `role=button` 触发只读详情；操作 footer 是其同级区域，恢复、继续、打开结果和删除均为显式按钮，并以组件测试验证键盘与单次事件。
- [规格与刚合入的未完成优先规则冲突] → 同一 change 对 `story2video-history-visibility` 提供完整 MODIFIED requirement，并在归档时同步主规格。
- [locale 迁移遗漏] → zh/en 成对提交，运行 locale sync 与 CJK baseline 门禁，并在英文 locale 组件测试中检查可见文案。

## Migration Plan

1. 先用纯函数和组件测试锁定新合同并确认旧实现失败。
2. 引入共享工具，更新父视图、子组件、composable、locale 和样式。
3. 运行定向单测、完整 renderer 测试、locale 校验、构建及桌面/窄屏视觉验证。
4. 更新 PRD、用户说明、CHANGELOG、决策与 learnings；完成双模型/降级留档审查。
5. 经 PR/CI 合并后归档 OpenSpec 与 CCG task；若回滚，只回退 renderer 与文档提交，不需要数据迁移。
