## Purpose

定义「一次任务的质量门禁执行记录」应当存在于何处、由谁在何时必须产出、它的收口状态与欠账登记如何被机器检查。目标是让"记录做在了检查不到的位置"这一形态从**设计上不可见**变为**可判定且默认变红**，同时不复用巨型置顶单文件与共享清单所带来的并发撞车代价。

## ADDED Requirements

### Requirement: 执行记录以「每 PR 一篇独立文件」为载体，且欠账登记随该文件走

系统 SHALL 把 `openspec/records/` 下的 Markdown 文件作为执行记录的正式载体：一个 PR 新增一篇记录文件，文件名在本 PR 内唯一。记录若处于未收口状态，其**登记信息（状态 / 原因 / 回填者）MUST 写在该记录文件自身内**；跨记录的聚合清单 SHALL 是派生产物，MUST NOT 要求多个 PR 向同一个共享文件头部插入内容。既有 `.quality-gates.md` 中的历史记录 SHALL 保持原样，MUST NOT 被迁移、改写或删除。

#### Scenario: 新 PR 写记录落在独立文件

- **WHEN** 一个 PR 在 `openspec/records/` 下新增一篇记录文件
- **THEN** 该文件被视为本 PR 的执行记录，收口检查覆盖它，且 `.quality-gates.md` 与任何共享清单均无需被本 PR 修改

#### Scenario: 两个并发 PR 各自写记录不得互相冲突

- **WHEN** 两个 PR 各自新增一篇记录文件（含各自的登记信息）且除此之外不改同一文件
- **THEN** 对二者做只读合并探测时必须判定为无冲突

#### Scenario: 未收口的记录自带登记字段

- **WHEN** 一篇新记录的 `远程同步` 状态为未收口
- **THEN** 该文件必须自带非空的原因与回填者字段；缺失即判不合规，而不是要求去追加一份外部清单

#### Scenario: 历史记录只读

- **WHEN** 引入本载体后任一 PR 需要新增记录
- **THEN** 既有 `.quality-gates.md` 的历史记录逐字保留；任何仅新增记录文件的 PR 对该文件的 diff 必须为空

### Requirement: PR 必须携带新增记录文件或显式豁免，且判定只作用于本 PR 自身的变更

系统 SHALL 对每个 PR 判定「本 PR 的变更集中是否包含一篇新增记录文件」；不包含时 SHALL 要求同 PR 携带一篇豁免文件（同样按 PR 独立成文件、逐条带非空原因）；两者皆无时门禁 MUST 以非零退出并输出可执行的修复指引。存在性判据 MUST 复用仓库内既有的"取本 PR 变更集"实现，MUST NOT 另立第二份 diff 口径。该判据 MUST 是 forward-only：MUST NOT 因历史记录缺失而使当前 PR 变红。

#### Scenario: 带记录文件的 PR 通过

- **WHEN** 本 PR 新增一篇记录文件且其内容满足记录格式要求
- **THEN** 存在性判据通过，退出码为 0

#### Scenario: 无记录且无豁免的 PR 变红

- **WHEN** 本 PR 既未新增记录文件，也未新增豁免文件
- **THEN** 判据以非零退出，输出指明「新增一篇 `openspec/records/` 记录文件」或「新增一篇带原因的豁免文件」两条出路

#### Scenario: 变更集取自同一实现

- **WHEN** 判据需要本 PR 的变更文件清单
- **THEN** 必须由既有判定实现提供的同一取源得到；若该取源无法读取所需事实（git 取证失败、base 不可解析），MUST fail-closed 判红并原样输出所用命令与错误输出

#### Scenario: 历史欠账不牵连当前 PR

- **WHEN** 仓库中已存在数十条「合并时未写记录」的历史 PR，而本 PR 自身携带合规记录
- **THEN** 本 PR 判为通过；历史缺失仅以计数形式可见输出，不参与拦截

#### Scenario: 扫描器看不见记录目录时不得判绿

- **WHEN** 记录目录不存在、无法枚举，或枚举过程中有目录读取失败
- **THEN** 判据 MUST 抛错并以非零退出，MUST NOT 把「零条记录」当成「零条违规」通过

### Requirement: 豁免按 PR 独立成文件，消费后以「可见优先、超阈拦截」收束

系统 SHALL 允许豁免在其生命周期内暂存，且 MUST NOT 要求携带豁免的同一 PR 删除它（合并即删分支，同 PR 删除不可实现）。检查 SHALL 统计「所指向分支在远端已不存在」的豁免数量：存在即输出为可见待清理计数；仅当该计数超过声明的阈值时判红。删除豁免 MUST 表现为删除其自身那个文件，从而零同行竞争。

#### Scenario: 被消费的豁免先可见不拦截

- **WHEN** 一篇豁免所指向的分支已不在远端（其 PR 已合并或已关闭），而该豁免文件仍在
- **THEN** 检查输出「待清理豁免 N 条」并点名文件，只要 N 未超过阈值即以退出码 0 通过

#### Scenario: 超过阈值才拦截

- **WHEN** 待清理豁免数达到或超过声明的阈值
- **THEN** 判据以非零退出，并指出删除这些文件即可放行

#### Scenario: 原因为空时拒绝

- **WHEN** 任一新写入的豁免文件原因为空或仅空白
- **THEN** 检查抛出错误并以非零退出

#### Scenario: 同一 PR 同时交记录与豁免即矛盾

- **WHEN** 某分支既存在记录文件又存在豁免文件
- **THEN** 判为矛盾并以非零退出，要求删除豁免文件

### Requirement: 每篇记录必须含门禁表与「远程同步」行，状态按闭合词表判定

系统 SHALL 要求每篇记录文件包含一张门禁表与一行 `远程同步` 状态；状态列 SHALL 按**闭合词表**判定是否收口，凡未知写法一律判为未收口（fail-closed）。词表与判定 MUST 复用既有实现，MUST NOT 出现第二份。

#### Scenario: 缺行即红

- **WHEN** 记录文件存在但整篇没有 `远程同步` 行
- **THEN** 判为不合规并以非零退出，指明该文件缺该行

#### Scenario: 未知状态按未收口处理

- **WHEN** 状态列出现词表之外的写法（例如"差不多好了"）
- **THEN** 判为未收口，必须携带该文件自身的登记字段，不得因词表未覆盖而放行

#### Scenario: 收口写法放行

- **WHEN** 状态列以词表内的收口前缀开头（`PASS` / `N/A` / `✅` / `已`）
- **THEN** 判为已收口，不要求登记字段

#### Scenario: 未收口必须自带登记

- **WHEN** 一篇新记录把 `远程同步` 写为未收口状态（合并前无法取证）
- **THEN** 同一文件内必须写明"由后续会话按离线取证结果回填并删除本登记字段"，回填者字段不得为空

### Requirement: 收口检查必须覆盖两个来源并使用同一份豁免面判定

系统 SHALL 让收口检查同时读取历史单文件与新记录目录，二者以同一套状态词表与同一套欠账语义处理，并 MUST 输出可区分的分源计数。当检查需要区分「纯文档变更」与「含运行行为变更」时，MUST 复用仓库内既有的单一判定实现所导出的白名单，MUST NOT 新增第二份白名单。

#### Scenario: 两源欠账合并进同一结论空间

- **WHEN** 历史单文件与新记录目录中各存在一条未收口的 `远程同步` 行
- **THEN** 检查结果必须同时列出两条，且二者标识形态（标题 vs 文件名）不重叠、可在同一判据下被登记与销账

#### Scenario: 空遍历不等于零欠账

- **WHEN** 收口检查在某一次运行中一条 `远程同步` 行都没有读到
- **THEN** 必须抛错而非报告通过

#### Scenario: 分源计数可比

- **WHEN** 检查输出现场证据
- **THEN** 必须分别给出历史源与文件源的记录数与未收口数，避免两个口径的指标被混为同一个历史趋势数

#### Scenario: 豁免面判定复用同一实现

- **WHEN** 判据需要知道某 PR 是否属于文档/流程类变更
- **THEN** 必须调用既有判定实现导出的白名单与函数；其自身故障时 MUST fail-closed 按含运行行为变更处理
