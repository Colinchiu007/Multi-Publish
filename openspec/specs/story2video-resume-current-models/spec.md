# story2video-resume-current-models Specification

## Purpose

定义 Story2Video 历史失败或中断任务恢复时的当前模型路由、已完成媒体复用、内容参数保留、语音兼容和未知远程任务边界，确保恢复流程可预测、可校验且不增加用户决策负担。

## Requirements

### Requirement: 恢复时未完成工作使用当前设置中的能力模型

历史任务从断点继续时，旧任务启动快照中的图片、语音、视频 provider/model 路由不得继续作为未完成工作的显式路由；文字推理和提示词优化也必须在实际调用时解析当前默认 LLM。

#### Scenario: 设置模型变更后继续
- **WHEN** 用户在任务失败后修改图片、语音、视频或文字推理模型，并在历史记录点击【从断点继续】
- **THEN** 已完成本地资产继续可用，所有未完成的对应调用使用当前设置中的 provider/model，且不出现模型选择器

### Requirement: 已完成本地资产按稳定场景序号复用

恢复流程必须在调用生成 provider 前，按 `scene index` 校验并复用有效的图片、音频或视频路径；不得仅因原资产模型与当前模型不同而重新生成。视频复用时必须保留已有的跨镜连续性元数据。

#### Scenario: 新旧资产混合
- **WHEN** 场景 1 有有效的旧图片/音频/视频结果，场景 2 尚未完成
- **THEN** 场景 1 原样复用，场景 2 使用当前设置生成，最终结果允许同时包含不同模型生成的资产

### Requirement: 恢复时保留内容参数并替换过期路由

恢复策略必须保留 prompt、场景序号、输入媒体、画面比例、voice ID、语速、音调、情绪、视频模式和选择比例等内容参数，只清理过期的 provider/model 路由字段；旧版本快照必须保持可读。

#### Scenario: 旧快照缺少模型元数据
- **WHEN** 版本 1 的历史快照没有当前模型标记或能力模型元数据
- **THEN** 快照仍可恢复，系统在内存中应用当前模型策略，缺失路由回退到当前设置，不要求数据迁移

### Requirement: 语音模型与旧音色不兼容时必须 fail closed

当前 TTS provider/model 不支持历史 voice ID，或现有 voice catalog/model 合同拒绝该组合时，恢复流程不得静默替换成无关音色或覆盖原有音频；必须沿用现有兼容错误、默认音色回退和 re-clone 合同。

#### Scenario: 当前模型无法使用旧克隆音色
- **WHEN** 未完成 TTS 场景携带的 voice ID 不被当前 provider/model 支持
- **THEN** 调用返回既有兼容错误或完成受控 re-clone，不能把空音频或错误音色报告为成功

### Requirement: 未知远程视频任务状态不得被伪造成完成

在当前快照未持久化远程视频 task ID 的前提下，恢复流程不得因为阶段中断就把未知的远程提交标记为完成，也不得使用新模型盲目查询旧任务；没有有效本地视频时沿用现有阶段级重试和失败回退合同。未来远程任务状态查询必须绑定原 provider/model。

#### Scenario: 远程提交后进程中断
- **WHEN** provider 可能已经接受视频提交，但进程在本地视频路径写入前退出
- **THEN** 恢复不伪造已完成视频，不宣称已查询未知 task，并按现有阶段级重试或图片回退流程处理

### Requirement: 历史继续保持单一步骤交互

历史记录的【从断点继续】保持一键操作；当前模型策略、资产复用、校验失败和 fail-closed 错误均由运行时和现有历史/诊断界面处理，不增加旧模型/当前模型选择器或确认弹窗。

#### Scenario: 一键继续
- **WHEN** 用户打开失败或中断的 Story2Video 历史记录并点击【从断点继续】
- **THEN** 系统使用当前设置恢复，或展示现有可操作错误，不要求用户选择模型
